# Вклад в SAQ QURYLYS

## С чего начать

Прочитайте [README](README.md), [архитектуру](docs/ARCHITECTURE.md) и [руководство разработчика](docs/DEVELOPMENT.md). Для исправления ошибки достаточно задачи с воспроизводимым примером. Изменение модели риска, хранения или доверия к AI сначала опишите в issue: какое поведение меняется и как его проверить.

Создавайте ветку от актуальной целевой ветки, например `codex/fix-dossier-filter`. Не включайте в commit чужие незавершённые изменения. Код распространяется по лицензии [MIT](LICENSE).

## Подготовка изменения

1. Воспроизведите проблему на DEMO или отдельной тестовой среде.
2. Внесите ограниченное изменение. Для ошибки добавьте проверку причины, когда это оправдано риском.
3. Выполните `npm run check`, `npm test`, `npm run build` и проверки затронутого слоя. Для документации проверьте ссылки и команды; полный браузерный прогон только из-за текста не требуется.
4. Обновите руководство. Для изменений компоновки приложите desktop/mobile снимки.
5. В PR опишите проблему, результат, проверки и ограничения. Для незапущенных проверок укажите причину.

## Контракты

- AI-гипотеза не равна факту; unknown не даёт риск-баллы.
- Команды проверяются клиентом и сервером. Сохраняйте `apply_command`, версию workspace и квитанции повторов.
- Историческая версия решения и PDF читают snapshot.
- Миграция добавляется отдельным SQL-файлом; применённые файлы не переписываются.
- Данные и файлы ограничены владельцем. Service role и provider key остаются на сервере.
- Веса и правила согласуются в TypeScript, SQL, Python и тестовых контрактах.

## Что не добавлять в Git

Не публикуйте `.env*` с реальными значениями, токены, status JSON Supabase, персональные данные, `node_modules`, `dist`, `.venv` и полный вывод тестов. `.env.example` содержит безопасные примеры.

У отобранного доказательства проверки должны быть дата, команда и привязка к коду. Новые прогоны сохраняются отдельно от исторической приёмки. Платная LLM требует согласованного бюджета и не включается в обычный CI.

Об уязвимостях сообщайте по [правилам безопасности](SECURITY.md).
