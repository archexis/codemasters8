# 02 — Publications, Filters & Working AI

**Роль:** обнаружить в рекламе потенциальное предложение денег и связать публикацию с конкретным объектом. Это основной демонстрируемый AI-сценарий из ТЗ.

## Страница «Публикации»

```text
Публикации                                         [+ Добавить публикацию]
[Поиск] [Площадка] [Дата] [Связь с ЖК] [Признаки оплаты] [Статус] [Сбросить]
Левая часть: лента карточек/таблица (с пагинацией)
Правая часть или drawer: выбранная публикация + оригинал + AI-гипотезы + привязка
```

Фильтры комбинируются, видны количество результатов и пустое состояние. В карточке: дата публикации, дата фиксации, платформа/аккаунт, URL, исходный текст либо скриншот, привязанный ЖК/очередь или `не сопоставлено`, статус проверки. Скриншот/копию текста сохранять с учётом прав доступа и источника.

## «Добавить публикацию» — обязательный ручной ввод

Три способа: вставить текст; URL с ручным текстом при недоступном парсинге; изображение с OCR/мультимодальной обработкой. URL сам по себе не обещает автоматический сбор. Поля: источник/аккаунт, дата исходной публикации (если известна), URL, текст/файл, время фиксации (назначает сервер), опционально ЖК и очередь. Сохранение работает **без закрытых гос-API**.

## AI, но не автосуд

Pipeline: `новый материал → OCR если нужно → нормализация → LLM/ML → строгое JSON-извлечение → runtime validation → показать цитату и вероятную связь → человек принимает/отклоняет AI-гипотезу (триаж) → кандидат в «Проверке» → уполномоченный аналитик подтверждает факт в Investigation Mode → детерминированный скоринг`.

Минимальный AI-результат:

```json
{
  "payment_offer": "candidate",
  "payment_type": "booking_fee",
  "amount_text": "300 000 ₸",
  "quote": "Бронь от 300 000 ₸",
  "quote_location": {"start": 21, "end": 39},
  "complex_candidates": [{"complex_id": "demo-01", "phase_id": "phase-2", "reason": "Совпадение названия"}],
  "uncertain_fields": ["phase_id"]
}
```

Схема примерная; индекс цитаты проверять относительно сохранённого канонического текста, а не слепо принимать `quote_location` от модели. Если точного фрагмента в источнике нет — блокировать принятие доказательства, предложить ручной выбор. Уверенность модели — эвристика, а не доказанная вероятность. Сопоставление по неуникальному названию не подтверждает связь автоматически.

## UX после анализа

1. Отображается **оригинал** слева и **предположение ИИ** справа, с подсветкой точной цитаты.
2. Пользователь выбирает правильный ЖК/очередь или оставляет `Не определено`.
3. «Принять гипотезу» и «Отклонить гипотезу» фиксируют **оценку предложения ИИ**, не изменение исходной публикации. Принятие передаёт кандидат в «Проверку»; **оно не начисляет R2/R3**. Для начисления аналитик подтверждает конкретный факт в Investigation Mode согласно `07`.
4. «Перейти к ЖК» открывает досье; «Добавить в дело» доступно, если активен Investigation Mode.
5. Ошибка LLM → публикация сохранена; можно попробовать позже, подтвердить вручную с источником. Не показывать заготовленный результат как живую модель.

## Модель данных

`Publication(id, source, account, publishedAt?, capturedAt, url?, originalText?, screenshotAssetId?, captureMethod, demo)`; `PublicationLink(publicationId, complexId, phaseId?, status, evidenceIds)`; `AIExtraction(id, publicationId, model, version, status, candidates, rawOutputHash)`; `FactAssertion` из `07`.

## Доставка и производительность

Списки — cursor pagination/серверные фильтры после порога данных; AI-задание асинхронно, retry с идемпотентным ключом, отображение pending/error/done. Не прогонять модель заново при открытии drawer или досье. Секрет модели только серверный.

## DoD

- 12+ DEMO публикаций и создание совершенно новой вручную.
- Извлечение цитаты о платной брони на **новом**, не заготовленном тексте; JSON проверяется, принятие/отклонение AI-гипотезы работает и не начисляет баллы без верификации факта.
- Фильтры, ссылка на ЖК, сохранение первоисточника, неизвестные поля и отказ AI обработаны.
