# 00 — Product, IA, User Journey

## 1. Задача

Продукт помогает аналитику МИО выявлять публикации с признаками привлечения денег в долевом строительстве, связывать их с конкретным ЖК/очередью и формировать проверяемый сигнал риска. **Не признаёт правонарушения и не отправляет материалы в госорганы автоматически.**

**Одна главная сущность интерфейса — досье ЖК/очереди.** Карта, публикации и реестры лишь три способа найти и открыть одно и то же досье. Никакого отдельного «X-Ray-экрана», «Режима связей» в глобальном меню или дублирующей страницы «Отчёт».

## 2. Информационная архитектура

```text
SAQ QURYLYS
├── /map                 Карта: где искать? (2D / 2.5D + X-Ray)
├── /publications        Публикации: какие предложения о деньгах?
└── /registries          Реестры: какой ЖК, компания, документ?
         |                |
         └───────┬────────┘
                 ▼
/complexes/:id?phase=:phaseId     Досье ЖК (режим чтения)
  ├── overview                  Обзор
  ├── verification              Проверка
  ├── relations                 Связи (Risk Web)
  └── timeline                  Хронология (Time Machine)
                 |
                 ▼  [Начать / Продолжить расследование]
/cases/:caseId?tab=...             ТО ЖЕ досье + панель дела + команды
                 |
                 ▼
         Предпросмотр сигнала → подтверждение/возврат → PDF/печать
```

`/cases/:caseId` переиспользует `ComplexDossierLayout`, а не копирует четыре вкладки в отдельные компоненты. Deep links `caseId`, `phaseId`, `tab`, `selectedEvidenceId` воспроизводимы; несохранённое состояние не теряется.

## 3. Верхний уровень

- **Карта**: поиск/фильтр риска, 2D/2.5D, X-Ray; клик → floating preview → досье. Не выполнять юридическую проверку в мини-карточке.
- **Публикации**: рабочая очередь рекламы с фильтрами и ручным добавлением; AI помогает распознать и связать; клик по связанному ЖК → досье. Подробности см. `02`.
- **Реестры**: **внутренний каталог** ЖК (основная подкатегория), организаций, документов/источников. Это не заявление, что все внешние реестры подключены. Из результатов → досье. Подробности см. `03`.

Глобальная шапка содержит только три раздела, поиск и профиль/состояние данных. Не добавлять «Риск», «ИИ», «Отчёты», «Расследования», «X-Ray» в главное меню.

## 4. Досье: 1/3 + 2/3

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ ← Назад  /  ЖК «Название»  /  Очередь     Риск + полнота данных   [Начать дело] │
├──────────────────────────┬──────────────────────────────────────────────────┤
│ 1/3 Визуальная область   │ 2/3 Единое досье                               │
│                          │ [Обзор] [Проверка] [Связи] [Хронология]        │
│ [Спутник | 3D* | Фото]   │                                                  │
│                          │ контент активной вкладки                         │
│ дата, источник, галерея  │                                                  │
│ [Развернуть]             │                                                  │
├──────────────────────────┴──────────────────────────────────────────────────┤
│ В Investigation Mode: статус дела · материалы · [Предпросмотр сигнала]       │
└─────────────────────────────────────────────────────────────────────────────┘
* 3D только когда модель существует; спутниковые данные могут не иметь даты.
```

- **Обзор** отвечает «Что известно об объекте и почему он в этой зоне риска?» — сводка, этап, девелопер, известные правовые основания, свежесть, подтверждённые факторы, публикации.
- **Проверка** отвечает «На чём основано каждое утверждение?» — факторы, источники, оригиналы PDF/скриншотов, сравнение извлечения с оригиналом, подтверждение/отклонение факта.
- **Связи** отвечает «Кто и с кем связан?» — Risk Web, граф/список, ссылки на доказательства.
- **Хронология** отвечает «Что изменилось и когда?» — события, отчёты по стройке, снимки дронов, сравнение периодов, осторожный вердикт.

Эти четыре вопроса исключают пересечения вкладок: факт подтверждается в «Проверке», связь исследуется в «Связях», изменение сравнивается в «Хронологии». Краткие сводки могут ссылаться на соседнюю вкладку, но не дублировать её интерфейс.

## 5. Режимы и действия

- **Чтение досье:** доступно без открытия расследования. Можно изучать документы, граф и хронологию; нельзя подтверждать сигнал или неявно записывать изменения.
- **Investigation Mode:** запускается одной кнопкой, создаёт/открывает дело (`caseId`) для ЖК/очереди. Вкладки те же; появляются «Добавить в дело», панель подтверждений, журнал действий, контроль полноты, предпросмотр и решение. См. `04`.
- **Экспорт:** не глобальная вкладка. Доступен из шапки дела или панели итогового решения. PDF берёт только сохранённый snapshot дела и поясняет статус.

## 6. Канонический UX-сценарий

1. Аналитик видит ЖК на карте с 2.5D и одним активным X-Ray, выбирает объект → floating preview → досье.
2. Альтернативно аналитик открывает «Публикации», добавляет новый текст/скриншот → AI показывает цитату о платной брони → оператор принимает/отклоняет **гипотезу ИИ** и выбирает ЖК/очередь (пока без начисления баллов) → досье.
3. В «Обзоре» виден риск и явно отмеченная неполнота данных.
4. Аналитик запускает/продолжает дело, в «Проверке» изучает исходный документ/публикацию, проверяет конкретные утверждения и фиксирует подтверждения с автором и датой.
5. В «Связях» / «Хронологии» исследует контекст; нужные элементы добавляет в материалы дела.
6. Автоматический скоринг пересчитывается **только по подтверждённым факторам**; карточка объясняет вклад каждого.
7. «Предпросмотр сигнала» → «Подтвердить сигнал» или «Вернуть» → PDF/печать. Журнал хранит акторов, время и основание решения.

## 7. UX-инварианты

- Всегда один выбранный `complexId` + `phaseId`; юридические документы от одной очереди не переносить автоматически на другую.
- Отсутствие данных ≠ отсутствие правового основания; серый/нейтральный статус отдельный от красной зоны риска.
- Любая метка `AI suggested`, `confirmed`, `manual`, `demo` имеет ясный смысл и не смешивается с статусом источника.
- «Вердикт ИИ» — гипотеза/наблюдение, не юридическое заключение.
- Переключение вкладок не перезагружает данные досье и не запускает AI заново.
- Узкие экраны: визуальная 1/3 становится сворачиваемым верхним блоком; вкладки сохраняются.

## 8. Почему отказались от старой структуры

Старый подход создавал четыре конкурирующие аналитические функции с собственными потоками. Новый использует один предмет расследования, один ledger доказательств, один скоринг и одно место для человеческого решения. Подмодули поставляют данные в досье и не создают отдельные «центры управления».
