# 06 — Time Machine, Construction Intelligence & Drone Photos

**Роль:** понять, *что изменилось во времени*, и на основании каких материалов. UI: вкладка **«Хронология»** в досье; выбранный период синхронизирован с визуальной областью слева.

## UI

```text
[Вся история | Документы | Стройка | Реклама | Решения]  [Период]
┌─ timeline / события / даты ───────────────────────────────────────────┐
│ Сентябрь 2026 • отчёт инженерной компании • план / факт / источник   │
│ Август 2026   • фото дрона • геопривязка / дата / ракурс             │
│ Июль 2026    • реклама • исходный снимок / статус подтверждения      │
└─────────────────────────────────────────────────────────────────────┘
[Выбрать две даты] [Сравнить]
Визуальная 1/3: соответствующий датированный кадр; справа: числовые различия
```

В общем режиме слева визуал ЖК, справа хронология. В режиме **«Сравнить»** нужны две большие картинки: раскрыть viewer поверх контента или временно использовать расширенный compare-layout. Не пытаться уместить два полноразмерных кадра в постоянные 1/3 ширины.

## События и две даты

Каждое событие хранит `occurredAt` (когда произошло по документу/на снимке) и `capturedAt` (когда система узнала/сохранила). Это принципиально: импортированный вчера отчёт за июль не становится событием октября. Если дата неизвестна — честно обозначить `Дата события неизвестна`, не позиционировать точкой с вымышленным числом.

Возможные события: публикация, обновление правового статуса, создание/отмена документа, инженерный отчёт, фото дрона, заявленная готовность, подтверждённая готовность, факт задержки, изменение связей, человеческое решение. Связь с документом обязательна для существенного утверждения.

## Construction Intelligence как сервис данных

Источники: инженерные PDF/отчёты, проверенные записи аналитика, датированные изображения. Выделять: объект/очередь, период, плановую и фактическую готовность (если есть в документе), плановый срок, факт отставания, ссылку на исходную страницу/таблицу. Данные R5/R6 становятся факторами только после проверки по `07`.

**Не строить ложную модель готовности по фотографии.** Визуальный анализ может предложить «возведён новый этаж/появились стены», но не утверждать «готовность 72%» без валидированной методики и привязки к проекту.

## Drone Photo Intelligence

Вход: фото или набор кадров, `takenAt` если известна, `uploadedAt`, ракурс, GPS/ориентиры (если есть), автор/источник, привязка к объекту. Обработчик: thumbnail → preview → оригинал по запросу; опциональный visual AI может выделить наблюдаемые изменения с пометкой `гипотеза`.

Сравнение двух дат: одинаковый/сопоставимый ракурс → можно подсветить изменённые области; разные ракурсы → только side-by-side, без бессмысленного pixel-diff. Снимок без подтверждённой даты НЕ выдавать за исторический. Видео/3D реконструкция — после MVP.

## Вердикт хронологии

Компактная итоговая сводка: `Период`, `Документально подтверждённые изменения`, `Визуальные наблюдения AI`, `Недостаточно данных/вопросы`, `Источники`. Модель не пишет «нарушение доказано». Кнопка «Добавить событие/отчёт в дело» доступна в Investigation Mode, а подтверждение применимости R5/R6 — во вкладке «Проверка».

## Производительность

Таймлайн подгружает страницу событий по cursor; изображения — несколько thumbnail + 1–2 preview; оригиналы только по запросу; PDF/CV — background jobs с кешем результатов. Смена даты не перезапускает рендерер глобальной карты и не регенерирует все изображения. См. `08`.

## DoD

Показаны 2+ периода с надёжными временными метками; выбор события синхронизирует визуальный контент; режим сравнения корректно различает сравнимые и несравнимые ракурсы; документальный источник открывается на нужной странице; аналитик может добавить событие в дело; отклонение факта не удаляет исторический артефакт.
