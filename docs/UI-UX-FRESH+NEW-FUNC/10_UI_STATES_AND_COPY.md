# 10 — UX States, Labels and Microinteractions

Цель: единый язык интерфейса, чтобы пользователь различал *риск*, *неполноту информации*, *гипотезу AI*, *статус документа* и *статус дела*.

## 1. Словарь статусов

| Объект | Значения для пользователя | Почему |
|---|---|---|
| Сведения | `Подтверждено`, `Требует проверки`, `Отклонено` | результат проверки утверждения |
| Реестр | `Источник доступен`, `Временно недоступен`, `Требуется вход`, `Данные загружены вручную` | техническая доступность ≠ факт |
| Риск | `Зелёная`, `Жёлтая`, `Красная` + **балл** | детерминированный скоринг, не общая тревога |
| ИИ | `Предположение ИИ`, `Цитата найдена`, `Требует подтверждения` | LLM не принимает юридических решений |
| Дело | `Черновик`, `На проверке`, `Подтверждено`, `Возвращено` | состояние рабочего процесса |
| Источник | `DEMO`, `Вручную`, `Импорт`, `Внешний источник` | происхождение не степень достоверности |

Плохие формулировки: `Незаконное строительство`, `Мошеннический ЖК`, `Отсутствует разрешение` без проверки всех механизмов. Хорошие: `Правовое основание не установлено`, `Проверено отсутствие применимого основания`, `Обнаружено предложение платной брони` с источником.

## 2. Главные CTA

- Карта, floating preview: **Открыть досье**, вторичная **Показать связи**.
- Досье (обычный режим): **Начать расследование** или **Продолжить расследование**.
- Публикация: **Проверить гипотезу**, **Принять гипотезу**, **Отклонить гипотезу** (триаж AI, не подтверждение R2).
- Проверка: **Подтвердить факт** / **Отклонить факт** — только конкретный claim.
- Risk Web/Time Machine: **Добавить в материалы дела** — не подтверждать автоматически.
- Investigation: **Предпросмотр сигнала** → **Подтвердить сигнал** / **Вернуть на доработку** → **Скачать PDF** / **Печать**.

Сигнальные решения показывать отдельно от проверки фактов и снабжать последствиями действия. Версия отчёта и audit после решения не меняются задним числом.

## 3. Состояния ключевых экранов

### Карта

`Пока нет геометрии здания — объект показан маркером.`
`2.5D недоступен на этом устройстве; показана 2D-карта.`
`Правовые сведения требуют проверки.`

### Публикации

`Публикация сохранена. Анализ ИИ ожидает выполнения.`
`Модель не смогла найти точную цитату — выделите фрагмент вручную.`
`Возможный ЖК определён; подтвердите очередь.`

### Реестры

`Реестр временно недоступен. Это не означает отсутствие разрешения.`
`Документ относится к другой очереди; применимость требует проверки.`
`PDF загружен. Извлечённые поля пока не подтверждены.`

### Связи

`Связь предположительная: совпадает название, документального подтверждения нет.`
`Показаны ближайшие 80 узлов. Раскройте фильтр для остальных.`

### Хронология

`У снимка нет даты съёмки — нельзя включить его в временное сравнение.`
`Ракурсы различаются; доступно сравнение рядом, без точной подсветки изменений.`

### Investigation Mode

`Добавлено в материалы дела; факт ещё не подтверждён.`
`Подтверждение R1 невозможно: не представлено достаточное доказательство отсутствия применимого основания.`
`Сигнальная карточка готова к проверке.`
`Вернуть на доработку: укажите, какие подтверждения необходимы.`

## 4. UX качества

- Вся карта и таблицы доступны по клавиатуре настолько, насколько это поддерживает картографическая библиотека; аналитические действия доступны через список/таблицу.
- Status labels не закодированы только цветом. Атрибуция базовой карты и источников всегда видима.
- У всех долгих задач есть состояние `pending / completed / failed / retry` и возможность продолжать другую работу.
- Прямое открытие `/cases/:id` не теряет текущую выбранную вкладку и не создаёт второе расследование.
- Не использовать полноэкранную загрузку приложения из-за одного сломанного внешнего реестра.
