# UX-переделка SAQ QURYLYS — мид-эффорт процесс реализации

Дата: 20 октября 2026. Статус: процесс к исполнению.
Основание: [финальный план](UX_REDESIGN_FINAL_PLAN.md) (пакеты 0–5, сценарии A1–A17), уточнение досье: [спецификация](UX_DOSSIER_SPEC.md) + [бриф](UX_DOSSIER_USER_BRIEF.md).

Этот документ — урезанная реализация финального плана под средний объём усилий. При расхождении с финальным планом для мид-объёма действует этот документ. Всё, что здесь помечено «Отложено», не считается провалом мид-приёмки, а фиксируется как долг.

## 1. Что такое «мид» в этом процессе

Полный план = 6 пакетов (0–5) + 17 сценариев + D1–D11 + пользовательская проверка на 3–5 аналитиках.
Мид = 3 рабочих пакета (M1–M3) + приёмка M4, покрывающие первый законченный результат из финала («пакеты 1–2: единое досье с Проверкой и Расследованием на тех же материалах») плюс минимально достаточные ввод и сводки.

Принцип мида: убрать дубли и дать сквозной сценарий «найти материал → проверить факт → подготовить заключение» без повторного поиска. Полировку (идеальный мобайл, идеальная печать, полный CSV-редактор, пользовательское исследование) — отложить честно, а не имитировать.

Целевой сценарий мида (тот же, что в финале, без изменений смысла):

```text
Карта / каталог / лента публикаций
                  ↓
       Выбранный объект и материал
                  ↓
       Оригинал + утверждения рядом
                  ↓
       Проверка факта в выбранном деле
                  ↓
       Краткое заключение → версия
```

PDF-экспорт в миде — базовая сохранность (старая версия открывается со своими фактами), без перфекта печатной вёрстки.

## 2. Входит / отложено

### Входит (обязательно к приёмке мида)

- Единая проекция материалов: одна строка на источник/область в Расследовании, включая публикации с artifacts. Сверки в Проверке ссылаются на тот же источник.
- Одна оболочка досье с пятью вкладками Обзор / Проверка / Связи / Хронология / Расследование. Маршруты `#/complexes/:id` и `#/cases/:id` — одна оболочка, плюс значение вкладки расследования (без параллельной оболочки дела).
- Общий просмотр материала: оригинал + утверждения рядом, в досье встроен без отдельной белой поверхности. Одна карточка для ленты, досье, каталога, хронологии, связей.
- Расследование = один список материалов дела. Связанные утверждения внутри материала. Три списка (источники/публикации/кандидаты) удаляются. Второй самостоятельной формы решения нет — действие ведёт в Расследование к тому же материалу и делу.
- Три решения с разными названиями: «Взять в проверку» / «Отклонить предложение» (AI), «Подтвердить факт» / «Отклонить факт» (факт), «Утвердить заключение» / «Вернуть на проверку» (заключение). Комментарии отдельно. Принятие AI-предложения не подтверждает факт, балла не меняет.
- Идемпотентное включение: «Добавить в дело» → «В деле», повтор не создаёт копию, повторная доставка не создаёт новое решение.
- URL-приоритет: явный контекст ссылки > сохранённые настройки > дефолты. Ссылка на материал восстанавливает его после перезагрузки. Несовместимые сохранённые фильтры не скрывают явно открытый материал.
- Общая форма добавления «Публикация / Документ / Наблюдение» на общей реализации, одна кнопка сохранения по типу, одно подтверждение. AI — только по запросу («Предложить факты с AI»), пустая AI-колонка заранее пол-экрана не занимает. Из досье/дела объект и очередь подставлены.
- Score только в Обзоре. Левая визуальная колонка постоянна на всех пяти вкладках, без внешней белой обёртки. Статус «Недостаточно данных» — рядом с баллом, шкалу риска не подменяет. Прогресс материала — «1 из 3 утверждено в деле», без скрытого объединения дел.
- Плоские Связи/Хронология без вложенных белых карточек. Журнал дела — только его действия.

### Отложено (не входит в приёмку мида, фиксируется как долг)

- Полноценный CSV-режим как табличный редактор: в миде — только один редактор выбранной строки + явный выбор при неоднозначном ЖК. Массовые кейсы и изыски сопоставления — вне мида.
- Перфект печатной/архивной вёрстки заключения: в миде — краткий предпросмотр + приложения по одному оригиналу на материал + сохранность старых версий. Тонкая типографика печати — долг.
- Идеальный мобайл 390×844: в миде — компактная идентификация, пять вкладок с горизонтальным скроллом и keyboard-навигацией, просмотр материала полным экраном с возвратом. Восстановление фокуса и позиции списка пиксель-в-пиксель — долг (базовый возврат достаточен).
- Пользовательская проверка на 3–5 аналитиках (цель 80% из финала): в миде не проводится, фиксируется как «не проведена», удобство не утверждается.
- Тонкая подпись «оценка объекта vs оценка дела vs оценка версии» в сложных переходах: в миде — обязательная подпись смысла у каждого показанного балла, без сложных переходных формулировок.
- Автоматические сверки с внешними реестрами, новая правовая модель, смена весов, новый AI-провайдер, новый 3D-движок, массовая чистка дублей — вне объёма (как и в финале).

## 4. Приёмка мида (must-pass)

Берётся подмножество A-сценариев финала. Остальные — долг, явно перечисленный в отчёте.

| № | Сценарий (из финала) | Ожидаемый результат в миде |
|---|---|---|
| A1 | Открыть добавление из досье | Одна шапка, подставленные ЖК/очередь, одна кнопка, один результат операции |
| A2 | Сохранить публикацию без AI | Материал в ленте и расследовании; сверка открывает тот же источник; ни один факт не подтверждён автоматически |
| A3 | AI-предложение и «Взять в проверку» | Оригинал и предложение связаны; балл неизменен; проверка доступна здесь же |
| A4 | Два утверждения из одного материала | Поля/комментарии не перетекают; прогресс 1/2 → 2/2 |
| A5 | Публикации SQ-001 при чужом сохранённом фильтре | Применён контекст SQ-001; видны его две публикации, а не все 13 |
| A6 | Материал → дело → назад → перезагрузка | Тот же материал, область, фильтры; исходник не ищется повторно (базовое восстановление позиции достаточно) |
| A7 | Повторное включение и повтор доставки | Один материал на сущность/область, одна привязка, без нового решения от повтора |
| A8 | Тот же факт в двух делах | Различимые результаты, переноса подтверждения нет |
| A10-база | Пустой и частично проверенный объект, desktop + 390×844 база | Компактная идентификация, пять вкладок доступны, пустая галерея не вытесняет содержание; «Недостаточно данных» рядом с оценкой; запуск дела — в Расследовании |
| A12 | Другой ЖК, затем форма нового материала | Нет чужой глобальной истории; журнал дела — только его действия |
| A15-база | Ошибка AI/загрузки/сохранения, устаревшая версия, смена сессии | Понятное локальное состояние; ручной сценарий доступен где допустим; безопасный повтор |
| A17 | Карта недоступна / каталог пуст / материал удалён | Список объектов доступен; состояние объясняет проблему и даёт переход |

Плюс ядро D из спецификации досье: компоновка (шапка 68–72px, фон `#F5F5F1`, один белый контейнер 14–16px, левая 30–32%), пять вкладок с линией ~3px и keyboard-навигацией, Score только в Обзоре, старые маршруты и aliases разрешаются.

Отложенные сценарии (долг, не блокируют мид): A9 (тонкие подписи переходов оценок — только базовая подпись смысла), A11 (пиксель-перфект мобайл-возврата), A13 (CSV beyond базового редактора), A14 (перфект сверки предпросмотр/экспорт — только согласованность фактов), A16 (расширение beyond существующих `legal-invariants` тестов).

После каждого пакета — затронутые тесты. Перед завершением:

```sh
npm run check
npm test
npm run build
npx playwright test tests/e2e/ux-target.spec.ts tests/e2e/ux-review.spec.ts tests/e2e/investigation-score.spec.ts tests/e2e/legal-invariants.spec.ts
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
```

Старые проверки текста/раскладки обновлять под новое поведение; проверки сохранности доказательств, расчётов и повторов сохранять содержательными. Сетевые/платные/production-проверки локальными не считаются. AI-ошибки/ожидание — детерминированными фикстурами, платный прогон не нужен.

## 5. Измеримый результат мида

- Одна строка материала на источник/область в Расследовании; сверки ссылаются на тот же источник.
- Одна форма выбранного факта; одна форма добавления на тип через общую реализацию; одна кнопка; одно сообщение успеха.
- Ноль повторных ручных выборов ЖК/очереди/материала в основном сценарии.
- Ноль новых копий от повтора включения/доставки (A7).
- Один полный оригинал на материал в приложениях заключения.
- У каждой оценки и решения указаны область и версия/дело (минимум — подпись смысла: объект / дело / версия).

## 6. Границы и завершение

Мид покрывает все 17 групп дублирования из второго аудита на уровне «дубль устранён», но глубину проработки CSV, печати, мобайла и переходных подписей оставляет долгом. Сохраняются: правила расчёта факторов, независимая проверка человеком, область очереди/периода, неизменяемые версии, происхождение источников, ручная работа.

Мид завершён, когда M1–M4 выполнены, must-pass таблица зелёная, `check/test/build` + браузерные и backend-проверки пройдены, а итоговый отчёт содержит: что вошло, список долга (отложенные A/D, непроведённые среды, непроведённая пользовательская проверка), сравнение «было → стало» на одинаковых данных (время, возвраты к списку, места вопросов — без выдуманных процентов ускорения).
