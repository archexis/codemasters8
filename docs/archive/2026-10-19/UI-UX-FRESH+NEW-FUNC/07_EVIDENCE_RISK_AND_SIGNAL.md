# 07 — Evidence, Deterministic Risk, Review & Signal Card (source of truth)

Это **канонический документ доменной логики**. UX и сервисы не имеют права определять собственные, отличающиеся веса и переходы.

## 1. Цепочка достоверности

```text
SourceArtifact (первичный файл/URL/текст; снимок + checksum + capturedAt)
  → ExtractedClaim (распознанный фрагмент, номер страницы, гипотеза модели)
    → FactAssertion (привязка к точному complexId/phaseId/периоду; review state)
      → RiskFactor (R1–R6 только для подтверждённых утверждений)
        → ScoreSnapshot (детерминированный балл и зона)
          → Case / SignalSnapshot → HumanDecision → PDF/Print
```

**Не путать:** происхождение (`demo/manual/import/official`), доступность источника (`ok/unavailable/needs_auth`), степень доказанности утверждения (`candidate/verified/rejected/unknown`) и статус дела (`draft/in_review/confirmed/returned`). «Официальная страница найдена» не равно «конкретное основание применимо к очереди».

В доказательстве нужны: первоисточник (URL или безопасно сохранённый файл), источник/аккаунт, время фиксации, исходная дата события (если есть), локатор цитаты или страницы, тип данных, checksum, субъект и очередь, подтверждающий аналитик и время решения по факту. `caseId` не создаёт дубликат доказательства, только связывает уже сохранённый артефакт.

## 2. Формула из ТЗ, стр. 3

| Код | Баллы | Точное условие включения |
|---|---:|---|
| R1 | +35 | **Установлено проверенными данными отсутствие применимого законного основания** по ЖК/очереди с учётом всех альтернативных механизмов; недоступность/отсутствие записи не равно R1 |
| R2 | +25 | Проверенная публикация с прямым предложением платного бронирования, депозита, первоначального взноса или аналогичной схемы; точная цитата и первоисточник |
| R3 | +10 | Проверенная датированная реклама жилья до ввода объекта в эксплуатацию |
| R4 | +15 | Проверенное коллективное обращение о привлечении средств по этому ЖК (ручное приобщение допустимо) |
| R5 | +10 | Заявленная и подтверждённая готовность с датами/источниками отличаются на ≥20 **процентных пунктов** |
| R6 | +5 | Документально подтверждён существенный простой или значимая просрочка |

`score = min(100, Σ weights(verifiedFactors))`. Неизвестные, отвергнутые и `AI candidate` дают **0**, но показываются в «Требует проверки».

**Зоны**: `green = 0..24`; `yellow = 25..59 ИЛИ score >=60 без verified(R1)&&verified(R2)`; `red = score>=60 И одновременно verified(R1)&&verified(R2)`. Не делать ошибку «60 = всегда красный».

**Правовой нюанс:** действующая применимая гарантия КЖК и утверждение об отсутствии всех применимых оснований для той же очереди/периода не могут одновременно считаться подтверждёнными; серверная валидация должна отвергать конфликт. Документ другой очереди не даёт автоматического покрытия. Если юридическая ситуация не установлена, показывать неизвестность и не начислять R1.

Контекстные признаки (налоговая задолженность, госзакупки, граф компаний, необработанные снимки дронов) НЕ добавляются в базовые веса R1–R6.

## 3. Review-модель

Отдельные операции:

- `attachEvidenceToCase` — ссылка на материал, **не подтверждение**.
- `proposeFact` — утверждение с цитатой и применимостью, `candidate`. Отдельное `reviewAiSuggestion(accepted/rejected)` относится лишь к качеству извлечения и **не превращает candidate в verified**.
- `verifyFact/rejectFact` — проверка конкретного факта человеком с контролем доказательств и аудита.
- `recalculateScore` — чистая детерминированная функция, без LLM.
- `previewSignal` — собирает снимок текущих проверенных данных и отмечает пробелы.
- `confirmSignal` / `returnSignal` — отдельное решение человека, с автором/временем/статусом.
- `exportSignalPdf` или `print` — документ из сохранённого snapshot, не из свободного ответа LLM.

Важно: сигнал **жёлтой зоны** может быть подтверждён как сигнал к ручной проверке, если его факторы доказаны. Не требовать R1+R2 для подтверждения любого дела; эта комбинация нужна **только красной зоне**. R1 без проверяемых доказательств не может стать verified даже при нажатии «Подтвердить всё».

После итогового решения хранить неизменяемую версию SignalSnapshot. Если новые доказательства меняют риск — создать следующую версию, прежний PDF и audit остаются проверяемыми.

## 4. Предпросмотр / PDF

Состав: идентификатор и дата сигнала; ЖК/адрес/очередь; застройщик/БИН; стадия; **применимое** основание и статус/дата его проверки; балл/зона; таблица подтверждённых факторов R1–R6 с ссылками; использованные публикации/документы; неизвестные поля/ограничения; ручное решение, актор, дата и статус; ссылки/список приложений; обязательная DEMO-маркировка для synthetic данных.

UX: `Предпросмотр сигнала` в шапке дела → проверка обязательных полей → если неполнота, показать её явно → аналитик подтверждает/возвращает → `Скачать PDF` / `Печать`. PDF или печатная версия достаточно по ТЗ; продуктовая рекомендация — рабочая PDF-выгрузка. Нет кнопки `Отправить в МИО`.

Генерацию PDF выполнять шаблоном (HTML→PDF или серверный renderer); LLM опционально даёт **предварительную** краткую формулировку, но числовые и документальные поля заполняются только из snapshot. Контроль ссылок, переносов длинных идентификаторов, кириллицы и воспроизводимости.

## 5. Исполняемые контрольные сценарии ТЗ

- **A:** правовое основание `unknown`; подтверждены R2=25 и R3=10 ⇒ 35, **жёлтая**, R1 отсутствует.
- **B:** доказано отсутствие всех применимых оснований; подтверждены R1=35, R2=25, R3=10 ⇒ 70, **красная**, ждёт решения человека.
- **C:** подтверждена применимая гарантия КЖК; обычная реклама R3=10 ⇒ 10, **зелёная**, отсутствие отдельного разрешения МИО не создаёт R1.
- **D (добавленный):** 60+ без пары R1+R2 ⇒ жёлтая.
- **E (добавленный):** недоступен государственный сайт ⇒ `unknown`, R1=0.
- **F (добавленный):** R5 = 19 п.п. ⇒ 0; R5 = 20 п.п. с источниками/датами ⇒ +10.
- **G (добавленный):** AI создал цитату, отсутствующую в оригинале ⇒ принятие заблокировано.
- **H (добавленный):** попытка подтвердить R1 при действующей применимой гарантии ⇒ отказ/конфликт.

## 6. Минимальные серверные инварианты

Подтверждающий пользователь берётся из авторизованной сессии, а не доверяется полю `reviewer` в JSON. Runtime validation команд: допустимые enum, неотрицательные значения и готовность в 0..100, существующий complex/phase/evidence, корректные даты, idempotency для повторов. Нельзя выдать `confirmed` обходом UI. Журнал статусов append-only; все решения транзакционны с optimistic concurrency/version.

## DoD

Новая публикация формирует кандидата; человек подтверждает, балл пересчитан и объяснён. «Подтвердить сигнал» и «Вернуть» реально сохраняют статус/автора/время. A/B/C и негативные кейсы проходят. Выгруженный PDF соответствует сохранённому snapshot и открывается без повреждений.
