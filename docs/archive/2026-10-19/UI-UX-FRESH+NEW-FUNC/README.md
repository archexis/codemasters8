## Модель продукта — одно предложение

**Найти объект или публикацию → открыть досье ЖК/очереди → проверить конкретные утверждения → при необходимости вести расследование → сформировать сигнал → человек подтверждает или возвращает → сохранить PDF/печать.**

## Основные границы

1. **Глобальная навигация ровно 3 пункта:** `Карта / Публикации / Реестры`.
2. **Досье ЖК — отдельный маршрут**, доступный из всех трёх разделов; вкладки `Обзор / Проверка / Связи / Хронология`.
3. **Investigation Mode — режим досье**, не новая глобальная вкладка и не синоним «Хронологии».
4. **X-Ray — представление данных** на основной 2D/2.5D-карте, не автономная БД.
5. **Registry Intelligence и Construction Intelligence — сервисы данных**, не вкладки первого уровня.
6. **Risk Web — вкладка «Связи»** и лёгкий опциональный контекст на карте.
7. **Time Machine — вкладка «Хронология»** со связью с визуальной 1/3-колонкой.
8. **LLM — помощник по извлечению сведений**, не юридический судья и не источник баллов.
9. **Сигнальная карточка PDF/печать — результат дела**, не четвёртый глобальный раздел.
10. **Текущий код сначала аудировать:** пользователь выбрал Svelte 5 + TypeScript как целевую архитектуру, но нельзя считать без проверки, что репозиторий уже соответствует стеку. Любая миграция БД — новой миграцией, не переписывать применённые.

## Ссылочная дисциплина

- UX routes и owner состояний — `00`.
- Все допустимые статусы утверждений и баллы — **только `07`** (канонический источник).
- Производительность, ограничения рендеринга и fallback — **только `08`**.
- Критерии сдачи/тесты — **только `09`**.
- Спецификации модулей ссылаются на канон, а не вводят конфликтующие правила.

## Не входит в обязательный MVP ТЗ

Публичные live API всех реестров, автоматический парсинг всего интернета, 3D-модель каждого здания, собственная ML-модель оценки процента готовности по снимкам дронов. Если внешние подключения отсутствуют, продукт обязан работать на честно маркированном seed, импорте и ручном вводе.
