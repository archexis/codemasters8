## 2. Финальный пользовательский сценарий для демо

```text
[Публикации] добавить новый текст с платной бронью
→ AI выделяет точную цитату, предлагает ЖК/очередь
→ человек принимает/отклоняет гипотезу ИИ и выбирает связь (без баллов)
→ [Карта 2.5D] X-Ray «Реклама» показывает соответствующий ЖК
→ floating preview → [Досье ЖК]
→ [Начать расследование] → [Проверка] подтвердить конкретный факт, документы и R-факторы
→ [Связи] → [Хронология]
→ [Материалы дела] → score+zone с доказательствами
→ [Предпросмотр сигнала] → [Подтвердить или Вернуть]
→ PDF/печать + audit автора и даты
```

Этот маршрут — **один** тест E2E; карта, реестры и публикации при этом остаются независимыми точками входа.

## 3. Правила A/B/C из ТЗ

- A: основание непроверено, прямая платная бронь + реклама ⇒ R2+R3=35, жёлтая, без R1.
- B: документально установлено отсутствие основания + депозит + реклама ⇒ R1+R2+R3=70, красная, ждёт человека.
- C: действующая применимая гарантия КЖК + обычная реклама ⇒ R3=10, зелёная; отсутствие отдельного разрешения МИО не создаёт R1.

См. полный канонический набор негативных тестов в `07_EVIDENCE_RISK_AND_SIGNAL.md`.

## 4. Порядок внедрения, чтобы не повторить архитектурные ошибки

Этапы означают зависимости, а не гарантированные сроки. Актуальную кодовую базу обязательно аудировать до изменений.

### S0 — Baseline и схема сущностей

Поднять существующий проект, определить фактический frontend/backend/map DB, проверить текущие 8+/12+, исходные 178+ тестов **только если они реально присутствуют**, состояние миграций, реальные route/schemas. Зафиксировать commit, baseline FPS и известные дефекты. Никакого массового переписывания.

### S1 — Core: evidence → facts → risk → signal

Runtime validation и доменные инварианты `07`, ручная публикация, ID ЖК/очереди, статусные операции, audit, deterministic score, PDF preview/print. Минимальный вертикальный срез A/B/C. Это **блокер всего проекта**.

### S2 — Publications AI (живой сценарий)

Новый текст → JSON extraction → подсветка цитаты → связывание и human review; ошибки модели/ключа. Встроить в существующий «Публикации», не строить новую AI-платформу.

### S3 — Map X-Ray + 2.5D (наш обязательный дифференциатор)

Реальные геообъекты/markers + 3 X-Ray темы, 2.5D, popover, переход в досье, 2D fallback. Работает на общих read models, созданных S1, и агрегатах S2. Если движок несовместим, использовать измеряемый technical spike до миграции.

### S4 — Досье и Investigation Mode

Упорядочить четыре вкладки и левый viewer, перенести review в «Проверку», дело в общий контекст, PDF в итоговую action. Весь E2E от публикации до решения.

### S5 — Registry + Construction import, Time Machine

Ручной импорт/локальные документы прежде онлайн-адаптеров; несколько отчётных периодов, сравнение, drone-фото, связка с R5/R6 без автоподтверждения.

### S6 — Risk Web

Граф/список в «Связях», source-backed edges, географический проекционный режим на карте, ограниченное число узлов. Использует ту же нормализацию БИН/ЖК.

### S7 — Stability / UX / GitHub / live demo

Сквозной прогон на D0, FPS на D1, проверка утечек, fallback офлайн, public repo, README, commit hash, доступность материалов. Если времени мало, урезать качество необязательных внешних коннекторов, а не ломать обязательный E2E или X-Ray+2.5D.

**Параллелизация:** S3 можно делать параллельно S1–S2, используя стабильные MapSummary fixtures; S6 можно начинать после определений сущностей из S1, без ожидания всех внешних реестров.

## 5. Проверка модулей как единого продукта

- Из «Публикации» перейти в ЖК, затем в дело и обратно: фильтры/контекст сохраняются.
- Из карты открыть очередь 2 с неизвестным разрешением, не получить незаконный R1.
- Принять цитату как AI-гипотезу → риск НЕ меняется; подтвердить соответствующий R2-факт в Investigation Mode → скоринг меняется во всех read models (карта/реестр/досье) без ручного refresh.
- «Связи»: добавить связь в дело → не добавлять баллы автоматически.
- «Хронология»: два периода, разные ракурсы → нет фальшивого pixel-diff или fake readiness.
- PDF предпросмотр совпадает с saved SignalSnapshot; автор и дата решения настоящие.
- Без внешних API базовые данные, AI на новых данных при доступной модели и PDF работают; если AI-сервис недоступен, честная ошибка и резервная запись для защиты, а не фиктивный ответ.
- Доступ по прямому URL к `caseId` и документам защищён авторизацией, нет leaked keys.
