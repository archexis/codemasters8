# 03 — Registries, Documents & Registry Intelligence

**Роль:** предоставить документы и сведения для проверки. «Реестры» — внутренний каталог объектов, а не панель десятка несвязанных сайтов.

## Состав глобальной страницы «Реестры»

Внутри ровно три подкатегории без дополнительной глобальной навигации:

1. **ЖК (по умолчанию):** название, адрес, застройщик/БИН, стадия, очередь, тип основания, актуальность проверки, риск, публикации; поиск, фильтры и переход в досье.
2. **Организации:** БИН, название, роль в проектах, связанные ЖК и документальные источники; не считать одинаковый номер телефона доказательством собственности.
3. **Документы и источники:** искать по номеру, ЖК/очереди, БИН, типу, дате; открыть исходный PDF/ссылку и статус извлечения/подтверждения.

**Не создавать отдельный параллельный «Реестр ЖК» в другой вкладке.** База ЖК — едина, карта и досье читают её же.

## Внешние реестры как адаптеры, не как UI-режимы

Потенциальные источники из предоставленного списка: Homeportal/КЖК, E-License, Qazreestr, eQurylys, eGov, КГД, реестр предпринимательства, кадастровая карта, data.egov.kz, реестр недобросовестных участников госзакупок, Ashyq Data. **Не утверждать автоматическую интеграцию без реально работающего адаптера.**

Разделить `seed`, `ручной документ`, `импорт CSV/PDF`, `открытый набор данных`, `online adapter (проверен)`; каждый имеет статус `проверено источником/непроверено`, время фиксации, URL/файл. Проблемы `timeout`, `captcha`, `needs_auth` → `источник недоступен`, а не `разрешения нет`.

## Проверка юридического основания

Поиск исключительно на уровне **ЖК → очередь → период → применимый способ**. Отдельный документ для другого ЖК или очереди не переносится автоматически. Учесть гарантии КЖК и применимые варианты с разрешением МИО. **R1 не возникает от пустой выдачи или 404**; R1 подтверждается только если аналитик документально установил отсутствие всех применимых законных оснований по целевому объекту и периоду согласно правилам ТЗ. Подробные правила — `07`.

## Импорт PDF и документов

```text
[+ Добавить документ] → тип + объект/очередь + файл/URL
→ импорт/парсинг в background job → показать страницу оригинала
→ AI/парсер извлекает поля с координатами/номером страницы
→ оператор проверяет и исправляет → сохраняется FactAssertion/Evidence
```

Встроенный PDF-viewer открывается **по запросу**. Для больших PDF извлекать нужные страницы, не отправлять весь файл в LLM. Отсутствие текстового слоя → OCR только на нужных страницах. Хранить checksum, MIME, число страниц, дату получения и ссылку на страницу/выделение.

## Роли источников

Homeportal/E-License/Qazreestr/Ashyq Data — потенциальные сведения об основаниях/объектах, с проверкой применимости; eQurylys и eGov — организации/регистрация; кадастр — географический контекст; КГД/госзакупки/предпринимательство — **контекст для исследования**, не законное доказательство отсутствия основания и не добавка к R1–R6. Поле в открытом датасете не считать автоматически разрешением МИО без анализа семантики/актуальности.

## UX в детальном досье

Из реестра выбирают документ → `/complexes/:id?tab=verification&evidence=...`; именно во вкладке «Проверка» аналитик подтверждает отдельные извлечённые утверждения. «Реестры» — каталог, «Проверка» — работа с фактами. Не вводить одинаковые кнопки подтверждения в двух местах.

## DoD

- ЖК доступны из каталога, поиск и переход согласованы с картой.
- Есть ручное добавление документа, привязка к очереди и исходный артефакт.
- Отображаются статусы `не проверено`, `подтверждено`, `источник недоступен` без ложного R1.
- Seed-функциональность работает без сети и без ключей внешних API.
