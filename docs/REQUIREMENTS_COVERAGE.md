## Соответствие ТЗ

ТЗ — 6-страничный кейс: сквозной сценарий (§2), модули (§3), данные (§4), скоринг и обязательный AI (§5–§6), техника/сдача/питч (§7–§9). Полная построчная карта — [docs/acceptance/requirements.md](acceptance/requirements.md). §11 (скрейпинг, Drone, Risk Web, Time Machine, полные RU/KZ режимы) в ТЗ явно помечен как идеи, а не обязательные модули, — за всем списком не гонимся.

Что реализовано из ядра:

- Сценарий от публикации до сигнала. Городской обзор с фильтром риска (`src/components/RiskMap.svelte`), карточка ЖК с застройщиком, стадией и статусом основания (`Detail.svelte`), привязка публикации с точной цитатой (`Analyze.svelte` + `src/lib/parser.ts`), балл и зона с подтверждающими материалами (`src/lib/scoring.ts`), сигнал с human confirm/return и выгрузкой (`Signal.svelte`, `src/lib/signal-snapshot.ts`). Полный путь проходится за ~5 минут по [сценарию демонстрации](DEMO_SCRIPT.md).
- Данные. 8 полноценных demo-карточек и 13 публикаций в `src/lib/seed.json`; ручное добавление без госAPI; локальная копия текста публикации (ad.text неизменяем, цитата — точная подстрока оригинала); сущности «Объект / Публикация / Сигнал» в `src/lib/types.ts` и миграциях; demo-маркировка чипами origin/status — факты и гипотезы визуально различимы.
- Риск и обязательный AI. Веса R1–R6 (35/25/10/15/10/5), cap 100, дедупликация кодов; красная зона только при R1+R2 и score ≥ 60; unknown = 0, гипотеза ≠ факт, confirm без доказательств блокируется (`src/lib/domain.ts` validateFactor + зеркальный SQL-валидатор). Настоящий LLM — через Edge Function `analyze` и только extraction R2/R3 с точной цитатой (до 6 гипотез); принимает или отклоняет человек, отказ сохраняется и переживает reload.
- Сдача. Запуск по README (`npm ci`, `npm run dev`), свободный стек без обязательного деплоя; тесты важной логики — unit + SQL в PGlite (`tests/unit/`), E2E desktop/mobile (`tests/e2e/`), cloud mock, pytest API, Deno edge; секретов в Git нет, seed без персональных данных и обвинений реальным компаниям.

Что добавлено сверх ТЗ — и зачем:

- Импорт реестров (API data.egov.kz, CSV/JSON-выгрузки, геокодирование). В ТЗ это лишь «дополнительный уровень» D10. Причина: рядом с вымышленным demo нужны настоящие объекты, но без выдумывания данных. Импорт создаёт отдельные карточки (`origin=import`), проверенные поля и решения не перезаписываются, каждая запись источника — `EvidenceArtifact` с provenance (способ получения, URL, время). Детали — [docs/REGISTRY_IMPORT.md](REGISTRY_IMPORT.md).
- Расследование и версионные решения. Углубление требований T04/T05 про контроль решений. Причина: одно подтверждение фактора — ещё не досье; у дела собственные факты, область очереди и период, а подтверждённое решение — неизменяемый snapshot с manifest файлов (`src/lib/investigation.ts`, `signal-snapshot.ts`, версии `signalVersions` + SQL `build_signal_version`). Пересмотр меняет текущую работу, прежняя версия и её PDF остаются побайтово теми же.
- Backup/restore ZIP с SHA256 (`BackupPanel.svelte`). Причина: localStorage/IndexedDB и workspace хрупки, а история решений — главная ценность. Полная копия — JSON + байты файлов + manifest; восстановление — только в пустое пространство, импортированные факты требуют повторной проверки.
- Серверный PDF, извлечение текста и OCR (`backend/app/pdf.py`, `ocr.py`, `document_jobs.py`). ТЗ разрешает печать ИЛИ PDF. Причина: браузерной печати хватает для DEMO, а подключённому режиму нужен воспроизводимый PDF строго по snapshot и текст из сканов (Tesseract `rus+eng`). Результат всегда непроверенный candidate: баллов не даёт, требует сверки с оригиналом.
- Галерея строительства и сравнение периодов (32 AI-иллюстрации). Мотив — §11 про Drone/Time Machine, но реализовано честно: это визуальный контекст demo, а не evidence. В ledger не пишется, баллы не начисляет, к очередям не привязывается.
- Граф связей и хронология (`RelationGraph.svelte`, `Timeline.svelte`). Мотив — §11 про Risk Web. Причина — навигация по объектам, организациям и аккаунтам; связь сама по себе баллов не даёт и владельца не доказывает.
- Подключённый режим (Supabase Auth, RLS, private Storage). ТЗ не требует мультипользователя. Причины две, обе архитектурные: ключ LLM обязан жить на сервере (BYOK в браузере недопустим), а персональные данные требуют изоляции. Состояние — JSONB `workspaces`, команды идут через `apply_command` с проверкой версии и квитанцией против повторов; RLS ограничивает workspace и файлы владельцем; FastAPI ходит с пользовательским JWT, service role ему не нужен.
