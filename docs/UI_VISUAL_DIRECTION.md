# Визуальное направление SAQ QURYLYS: строгая аналитическая система, а не consumer SaaS

Дата: 20 октября 2026. Статус: обязательно к применению при реализации UX_REDESIGN_MID_EFFORT_PLAN.md (пакеты M2–M3) и проверке в M4.
Основание: отзыв о текущем UI — слишком мягкий, дружелюбный, безобидный. Светлая тема сама по себе не проблема; проблема — сочетание пастельности, мягкой геометрии, низкого контраста, декоративных контейнеров и слабой иерархии.

## Главный принцип

Интерфейс предъявляет результаты проверки, а не предлагает ознакомиться с информацией. Точный, строгий, убедительный. Декоративность — только если повышает скорость анализа; все, что существует «чтобы выглядело приятно», убирается.

## 18 обязательных требований

1. Геометрия: убрать чрезмерные скругления. Карточки, кнопки, поля ввода, табы, панели — малый радиус (2–4px) или прямые углы. Никакого «мягкого consumer SaaS».
2. Палитра: убрать пастель как основу (бежевый, пастельный зеленый, приглушенный желтый — не базовые фоны). Нейтральная строгая шкала: белый/холодный серый фон, графит/черный текст, один сдержанный акцент для действий. Цвет — носитель смысла (статус, риск), а не уюта.
3. Контраст: основной текст — почти черный; вторичный — четко читаемый серый, а не бледный. Границы видимые. Сильное разделение главного и второстепенного.
4. Контейнеры: резко сократить белые карточки. Связанные блоки — на общем фоне с разделителями, а не каждый в собственном контейнере. Ощущение единой рабочей среды, а не набора виджетов.
5. Ноль «карточек в карточках»: вложенные поверхности, рамки и отступы без функциональной нагрузки — убрать. Особенно блок визуальных материалов и панель объекта на карте.
6. Плотность: уменьшить внутренние отступы, высоты блоков, расстояния между элементами. Интерфейс собранный, информационная плотность высокая (без ущерба читаемости).
7. Иерархия: название объекта, оценка риска, сведения застройщика, правовые основания, результаты проверки — четко различаются визуальным весом. Критически важные данные доминируют размером, насыщенностью, позицией.
8. Риск-скор: не декоративная метрика. Подача соответствует значимости: крупный строгий числовой показатель, вес и цвет по уровню риска, без «безобидной» светло-желтой пилюли. Число 35 должно выглядеть как оценка риска, а не бейдж.
9. Кнопки: строгие рабочие контролы — четкая форма, достаточный размер, видимый приоритет (основное/вторичное/опасное действие различаются). Не «элементы приложения для повседневных задач».
10. Типографика: строгая — заголовки с весом и кеглем по уровню, метаданные компактные и читаемые, числовые показатели — табличные цифры, выровненные, с весом. Ощущение точности, не легкости.
11. Структура данных: блоки сведений об объекте — как техническое/юридическое досье: строки с четкими разделителями (линии, а не только воздух), подписи полей единообразно, значения выровнены.
12. Факторы R1–R6: подача как результаты серьезной проверки — статус, основание и вклад каждого фактора выразительны (вес, маркер статуса, связь основание→вклад). Не «список настроек».
13. Статусы: подтвержденный факт, отсутствие данных, непроверенная информация — явно разная визуальная интенсивность. Различия между ними считываются мгновенно.
14. Панель карты: полноценный рабочий инструмент — непрозрачный фон, строгие границы, плотная компоновка. Не плавающий виджет.
15. Единый ритм: зафиксировать токены — радиусы, отступы, высоты, типы контейнеров — и применять везде одинаково. Ощущение дисциплины и системности. Разнобой фиксировать как дефект в M4.
16. Идентичность: визуальный язык должен говорить «расследование, мониторинг нарушений, проверка доказательств» — сдержанная официальность, а не каталог ЖК. Проверить узнаваемость: скриншот не должен путаться с CRM недвижимости.
17. Утилитарность выше декоративности: каждое визуальное решение обосновывается скоростью/точностью анализа. Остальное — кандидат на удаление.
18. Авторитетность: точность, контроль, нейтральность, институциональная строгость — итоговый критерий приемки визуала.

## Применение в пакетах мида

- M1: без визуальных изменений, только структура.
- M2: оболочка досье (единственный белый контейнер из FINAL-плана — держать, но строгий: малый радиус, видимая граница), общий просмотр материала без вложенных белых поверхностей, форма факта, три решения с визуально различимым весом.
- M3: компактная идентификация, score только в Обзоре по п.8, плоские Связи/Хронология, карта по п.14, типографика и токены по п.10/15, app.css — палитра и контраст по п.2/3.
- M4: визуальные регрессии — скриншоты до/после на одинаковых данных; пункты 1–18 проверяются чек-листом в отчете (каждый пункт: выполнено/долг с причиной).

## Что НЕ делать

- Не возвращать пастель, крупные радиусы, карточки-в-карточках под видом «полировки».
- Не выпускать декоративные правки как завершение переделки (действует правило FINAL-плана).
- Не снижать контраст и плотность ради «воздушности».
