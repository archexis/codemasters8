# Визуальное направление SAQ QURYLYS v2: investigative terminal (итерация жесткости)

Дата: 20 октября 2026. Статус: обязательно к применению. Заменяет и конкретизирует v1 (docs/UI_VISUAL_DIRECTION.md): вместо «стало строже» — точные токены, размеры и конструкции ниже.
Основание: отзыв по скриншотам после M1–M4 — интерфейс остался «аккуратной админкой», а не жестким инструментом проверки и расследования.

## Главный принцип (не меняется)

Строгость, сухость, уверенность, безэмоциональность. Институциональная аналитическая платформа с высокой плотностью данных. Строгость НЕ равна агрессивности: визуальный авторитет — от объективности, доказательств и точности. Система не признает застройщика виновным своим видом.

## Токены (заменить прежнюю палитру)

- Основной текст: #101714
- Фон приложения: #E3E6E4
- Поверхности панелей: #F5F6F4
- Основной темный (шапка, структурные области): #14241E
- Границы: #A9B2AC
- Второстепенный текст: темнее прежнего — остается второстепенным по размеру/весу, но не выглядит выцветшим.
- Цель: почти графическая четкость, а не набор мягких оттенков.

## 10 конкретных изменений (в порядке приоритета влияния)

### 1. Убрать карточный дизайн → panel-based (влияние: очень высокое)
- От card-based к panel-based: единая рабочая поверхность, секции разделяют линии и сетка, а не воздух между плавающими прямоугольниками.
- Убрать тени полностью везде.
- Скругления максимум 2–4px (радиус-токен уменьшить с 3px до 2px где уместно, потолок 4px).
- Секции разделять линиями; соседние области — общие границы; каждый элемент не в отдельном контейнере.
- Ориентир: ближе к инженерной программе, чем к Notion.

### 2. Радикально усилить контраст (влияние: очень высокое)
- Токены выше. Текст, линии, подписи, границы — жесткие, холодные. Никакой серо-зеленой бледности.
- Сохранить семантические цвета зон/статусов только как носители смысла (статус, риск), не как декор.

### 3. Уплотнить интерфейс на 25–35% (влияние: очень высокое)
- Заголовок объекта: с ~42px до 30–34px.
- Вертикальные промежутки: с 24–32px до 12–16px.
- Высота фильтров: 36–40px.
- Отступы внутри панелей: 16–20px.
- Сократить расстояние между заголовком и рабочими вкладками.
- При открытии объекта пользователь сразу видит данные, а не визуальную «шапку». Рабочая поверхность, не лендинг.

### 4. Темные структурные области (влияние: высокое)
- Темный фон (#14241E) ровно в трех местах: глобальная верхняя навигация; заголовки ключевых аналитических панелей; блок оценки риска и его расшифровки.
- Остальное — холодный серый фон + контрастный текст + четкие линии.
- Не делать весь интерфейс темным (не имитация хакерского терминала).

### 5. Типографика: техническая (влияние: высокое)
- IBM Plex Sans — основной интерфейс. Подключить локально через npm-пакет (@ibm/plex), а не внешним линком, чтобы сборка работала офлайн.
- IBM Plex Mono — только там, где важна точность: даты, БИН, ID объектов, оценки риска, координаты, системные метаданные. Не везде.
- Табличные цифры для числовых показателей.

### 6. Табы как системная навигация (влияние: высокое)
- Убрать зеленоватую заливку активного таба. Строгие табы на общей горизонтальной линии, активный — темная полоса-индикатор 2–3px + насыщенный текст + повышенная жирность. Неактивные нейтральные.
- Табы не выглядят как кнопки.

### 7. Хронология как forensic log / audit trail (влияние: высокое)
- Каждое событие — формальная проверяемая запись: дата (моно), ID события (EVENT 001), заголовок, описание, источник/фиксация строкой.
- Формат: ЖУРНАЛ СОБЫТИЙ + счетчик записей; дата; EVENT id; заголовок; описание; источник (напр. «Krisha (демо) · @demo_official_3»).
- Не выдумывать статусы/источники ради эстетики — строгость только на реальных данных.

### 8. Строгие empty states (влияние: среднее)
- Убрать «милый» empty state: большой прицел, пунктир, дружелюбные подписи.
- Формат: заголовок блока + «ИЗОБРАЖЕНИЕ НЕДОСТУПНО» / «Датированный снимок не предоставлен» + «ДАТА НАБЛЮДЕНИЯ — НЕ УСТАНОВЛЕНА». Сухо, капсом для меток, без иллюстраций.
- Никаких пунктирных upload-зон вне режима загрузки документа.

### 9. Жесткие контролы (влияние: среднее)
- Селекты, даты, кнопки — элементы инструментальной панели: одинаковая высота, прямоугольные границы, явный фокус, насыщенный текст, скругления минимум, ноль теней.
- Убрать эффект «каждый input — маленькая карточка». Фильтры — одна непрерывная горизонтальная панель, группы разделены границами.

### 10. Темная верхняя панель (влияние: среднее, но задает тон всему)
- Header 64–72px, фон #14241E, без теней и мягких переходов: «SAQ QURYLYS / СИСТЕМА МОНИТОРИНГА РИСКОВ», навигация КАРТА / РЕЕСТРЫ / ПУБЛИКАЦИИ, справа ДЕМО. Как верхняя панель специализированной рабочей станции, не навигация сайта.
- Тёмно-зелёный бренда — доминирующий институциональный цвет, не декоративный акцент.

## Проверка приемки

- `npm run check` 0 ошибок, `npm test` все зеленые, `npm run build` успех; затронутые e2e обновить и прогнать (ux-review, ux-target, ux-geometry, workflows).
- DOM-ассерты + 3–5 скриншотов ключевых экранов (досье/обзор, расследование, хронология, карта) в отчет; сравнить с v1 по чек-листу: светлота/воздух/границы/контраст/подача.
- Не ломать must-pass M1–M4 (две публикации ЖК, идемпотентность, два дела, материал→факт→решение, URL-приоритет).

## Что НЕ делать

- Не превращать в «темную тему ради темной темы» и не в агрессивный обвинительный UI.
- Не возвращать тени, крупные радиусы, карточки-в-карточках, пастель, пунктирные плейсхолдеры.
- Не снижать плотность ради «воздушности». Не выдумывать данные ради строгости.
