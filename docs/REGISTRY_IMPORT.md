# Импорт реальных данных

В «Реестрах» доступен поток «Получить данные» → предпросмотр → «Импортировать выбранные». Допустимые строки выбраны заранее; конфликты и уже сохранённые источники исключены. До второго нажатия рабочее пространство не меняется. Демонстрационные объекты не удаляются и не превращаются в реальные: импорт создаёт отдельные карточки с `origin=import`, `demo=false`.

## Источники и настройка

| Источник | Доступ в этой реализации |
| --- | --- |
| data.egov.kz | API v4 после настройки оператором; либо CSV/JSON |
| eQurylys, Homeportal | Подготовленные разрешённые CSV/JSON-выгрузки |
| Krisha.kz, Developers.kz | Подготовленные разрешённые CSV/JSON-выгрузки |

Наличие публичной страницы не означает, что для неё подключён API. Сбор HTML коммерческих каталогов не выполняется. Пустые/недоступные источники показываются отдельно и не заменяются вымышленными объектами. Статус `available` означает получение ответа, а не подтверждение фактов.

Для сервера примените миграцию `supabase/migrations/20261020000100_registry_import.sql` обычным процессом проекта. Она добавляет транзакционный RPC поверх действующих проверок `apply_command` и разрешает пустую дату сверки только для неизвестного правового основания. Квитанции используют существующую таблицу с изоляцией по владельцу. Функция доступна только `authenticated`; JWT проверяется FastAPI через Supabase Auth. Service role для импорта не нужен.

Серверные переменные:

| Переменная | Значение |
| --- | --- |
| `EGOV_API_KEY` | Ключ data.egov.kz, только на сервере |
| `EGOV_DATASET` | Точное значение `dataset/version` из паспорта выбранного набора |
| `EGOV_FIELD_MAP` | JSON-сопоставление канонических полей с именами столбцов набора |
| `EGOV_CITY_QUERY` | Запрос по столбцу города, по умолчанию `Усть-Каменогорск` |
| `IMPORT_DB_PATH` | Постоянный локальный volume для SQLite-предпросмотров, по умолчанию `backend/.data/imports.sqlite3` |
| `GEOAPIFY_API_KEY` | Необязательно: включает поиск координат для адресов без координат |

Оператор должен выбрать подходящий **набор строительных объектов ВКО** и проверить его схему. Набор не выбран автоматически. Пример **синтаксиса**, имена столбцов здесь условные:

```dotenv
EGOV_FIELD_MAP={"name":"object_name","city":"city_name","address":"object_address","developer":"developer_name","developer_bin":"bin","observed_at":"source_date","lat":"latitude","lng":"longitude"}
```

Обязательны соответствия `name`, `city`, `address`; БИН из источника должен быть строкой. API обращается только к `https://data.egov.kz/api/v4/{dataset}/{version}`, без перенаправлений. Ключ не возвращается браузеру, не входит в сохранённые ссылки и сообщения об ошибках. Ответ ограничен 2 МБ и 100 строками. Если результатов больше, требуется уточнить выборку или подготовить несколько выгрузок; полнота всего городского реестра не заявляется. После запроса каждый город дополнительно проверяется, допустимы Өскемен/Оскемен/Усть-Каменогорск/латинские варианты.

Документация API: [data.egov.kz — примеры запросов](https://data.egov.kz/pages/samples).

## Выгрузки

Загрузите CSV UTF-8 или JSON-массив через «Подготовленная выгрузка». Лимиты: 100 строк, 2 МБ. Файл Excel нужно предварительно сохранить как CSV UTF-8. Данные организаций импортируются в контексте объекта: отдельный список юрлиц сначала необходимо сопоставить с объектами по БИН.

Пример структуры, **условные значения, не реальные сведения**:

```json
[
  {
    "name": "Название из выгрузки",
    "city": "Өскемен",
    "address": "Адрес из выгрузки",
    "developer": null,
    "developer_bin": null,
    "construction_status": "unknown",
    "source_url": "https://krisha.kz/complex/search/ust-kamenogorsk/",
    "observed_at": null,
    "lat": null,
    "lng": null
  }
]
```

Обязательны `name`, `city`, `address`, `source_url`. Статусы строительства: `unknown`, `planned`, `under_construction`, `commissioned`, `on_hold`. Неизвестная дата — `null` или пустое поле, известная — реальная календарная `YYYY-MM-DD`. URL должен относиться к выбранному источнику, использовать HTTPS и не содержать ключ API. `source_type` выводится из домена, `verification_status` всегда `unverified`; значения доверия из входного файла не принимаются. БИН — текст из 12 цифр, начальные нули сохраняются.

## Сопоставление и история

Объекты группируются по нормализованным городу, названию и адресу. Учитываются регистр, Unicode, пунктуация и префикс «ЖК». Совпадение одного БИН не объединяет разные здания. Разные БИН/застройщики/стадии/координаты внутри группы, неоднозначное совпадение с существующими объектами и частичное совпадение названия либо адреса требуют ручного сопоставления; такие строки импортировать нельзя. Уточните исходную выгрузку и повторите предпросмотр либо используйте ручную карточку. Нечёткое/транслитерированное сопоставление не выполняется.

Для новой карточки сохраняются сведения об объекте, но законное основание остаётся `unknown`, score — 0 до решений аналитика. Существующие карточки дополняются материалами без перезаписи проверенных полей, факторов, решений и версий сигнала. Новые значения из источников доступны для ручной актуализации. Полностью повторённая строка источника не создаётся второй раз; изменение содержательных полей либо даты создаёт новую фиксацию. Простое повторное получение идентичного содержания не добавляет копию.

Каждая запись источника — отдельный `EvidenceArtifact`, `origin=import`, с исходными значениями, URL, типом источника, способом получения (`egov_api`/`prepared_export`), датой источника и временем получения. Полная структура хранится в неизменяемом тексте `saq-registry-source/v1`; существующие серверные механизмы фиксируют SHA256, размер, время записи и аудит. Эти материалы доступны в «Проверке», «Связях», «Хронологии», в каталоге документов и резервной копии. Дата получения не становится датой исходного события. Коммерческий каталог не подтверждает разрешение; открытый государственный набор также требует проверки применимости.

## Координаты

Координаты из выгрузки проверяются на формат и диапазон; они остаются непроверенным заявлением источника. При отсутствии координат настроенный Geoapify пытается найти до 20 уникальных новых адресов за предпросмотр (до 4 одновременных запросов, общий бюджет времени 15 секунд). Принимается единственное совпадение уровня здания в Өскемене с confidence ≥ 0.95, совпадением улицы и номера дома. Центр улицы/города, несколько результатов, ошибка и низкая уверенность оставляют координаты пустыми для ручной проверки. На карте произвольные точки не появляются.

Исходные координаты источника не заменяются результатом геокодирования: он сохранён отдельно с запросом, временем, confidence, возвращённым адресом и атрибуцией провайдера. Сведения геокодера не подтверждают правовой статус. Без `GEOAPIFY_API_KEY` или в локальном режиме геокодирование отключено. [Документация Geoapify](https://apidocs.geoapify.com/docs/geocoding/forward-geocoding/).

## API и повторные запросы

```text
POST /api/imports/preview  {"sources":["egov","krisha"],"records":[]}
POST /api/imports/commit   {"job_id":"…","selected_ids":["IMP-…"]}
GET  /api/imports/{job_id}
```

Все маршруты требуют Bearer JWT и инициализированного workspace. Предпросмотр хранится 24 часа с изоляцией по владельцу; максимум 30 сохранённых предпросмотров на владельца. SQLite не содержит JWT и ключей API. Требуется постоянный локальный volume; копии SQLite на разных хостах не образуют общую очередь.

Commit принимает только выбранные ID из серверного предпросмотра. Первый запрос фиксирует выбор и пакет команд. Изменение workspace после preview даёт 409 и требует нового предпросмотра. Все команды и квитанция пакета выполняются в одной транзакции. При потере ответа повторяется тот же job/выбор, и серверная квитанция предотвращает повторную запись. Другой выбор после начала commit отвергается. `GET` возвращает `preview`, `committing` (результат доставки ещё не подтверждён) или `committed`. После неопределённого результата нужно повторить исходный commit.

В локальном режиме CSV/JSON обрабатывается в браузере и сохраняется действующими командами DEMO workspace. Запись локального пакета последовательная: при ошибке показано число доставленных команд, повтор продолжает те же ID. Транзакционность всего пакета обещается только для серверного режима. Локальные записи сохраняются в этом браузере и удаляются при сбросе демо.

Проверки: `tests/unit/registry-import.test.ts`, `tests/unit/registry-import-sql.test.ts`, `backend/tests/test_registry_import.py`. Mock-проверки API не подтверждают доступность выбранного набора data.egov.kz и реального Geoapify. Функция не подключает внешние реестры без операторской настройки и не наполняет рабочее пространство автоматически при открытии страницы.
