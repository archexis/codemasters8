# Аудит дублирования и перегрузки SAQ QURYLYS

Порядок реализации и итоговые решения зафиксированы в [финальном плане переделки UX](UX_REDESIGN_FINAL_PLAN.md). Этот аудит содержит доказательства проблем; при расхождении рекомендаций использовать финальный план.

20 октября 2026. Дополняет и уточняет первый UX-аудит. Приоритет — сокращение повторной информации и работы, а не добавление новых экранов.

## Диагноз

У одной задачи слишком много самостоятельных представлений. Один источник выглядит как публикация, материал, событие хронологии и основание связи. Одно решение выглядит как принятие гипотезы, подтверждение факта и подтверждение сигнала. Сами различия в модели данных полезны, но интерфейс заставляет пользователя вручную обслуживать каждое из них.

Перегрузка складывается из четырёх вещей:

1. Повторный показ того же содержания.
2. Несколько названий и кнопок для сходных или одинаковых действий.
3. Повторный выбор уже известного контекста.
4. Постоянные объяснения различий, которые интерфейс сам сделал неочевидными.

Первоначальная рекомендация добавить очередь проверок была преждевременной. Сначала нужно свести существующие представления к общим карточкам и формам; иначе новый экран увеличит дублирование.

## Метод и границы

Просмотрены активные компоненты Publications, Analyze, ComplexDossier, RegistryCatalog, Relations, Timeline, CaseSignal, MediaCard, ComplexForm, ReadinessObservation, PhaseReadiness; проверены маршрутизация, read models и команды регистрации материалов. Detail/Signal проверены отдельно на достижимость.

В браузере подтверждены двойная шапка добавления публикации, состав пустой проверки и потеря фильтра ЖК при переходе из досье. Остальные указанные ниже ветки установлены чтением кода; сохранения решений, загрузки файлов и платный анализ не выполнялись. Рабочая копия меняется параллельно, номера строк — ориентиры данного просмотра.

## 1. Одна публикация разложена на три вертикальных списка — P1

**Где:** ComplexDossier.svelte:119–122.

В «Проверке» последовательно идут «Источники и проверка утверждений», «Сохранённые публикации ЖК», «Кандидаты в проверку». Первый список берёт artifacts, второй — все ads объекта, третий — claims. Публикации, уже представленные в artifacts, из второго списка не исключаются. При открытом источнике текст виден в нём и в списке публикаций; ниже повторяется цитата кандидата.

Это заставляет сопоставлять блоки по памяти. Разные тексты кнопок — «Добавить в дело» и «Внести первоисточник в дело» — дополнительно создают впечатление разных процедур. У первого действия есть состояние «В деле», у второго оно не показывается.

**Изменение:** один список материалов, идентичность публикации сохраняется по adId. В карточке материала — источник, состояние включения в дело, раскрываемый оригинал и связанные утверждения. Подтверждение факта остаётся отдельным осмысленным действием внутри этой карточки. Уже добавленный источник показывает единое состояние «В деле» во всех представлениях.

## 2. Две кнопки сохранения означают одно и то же — P1

**Где:** Analyze.svelte:278 и 290; реализация saveMaterial:49–136.

«Сохранить материал без AI» и «Сохранить без подтверждения» вызывают один saveMaterial() без аргументов. После получения анализа обе присутствуют на странице. При актуальном result эта функция может сохранить analysis и при нажатии «без AI»: название не описывает фактическое действие. У кнопок различаются условия disabled, что делает их ещё менее предсказуемыми.

**Изменение:** одна кнопка «Сохранить публикацию». Анализ — отдельная дополнительная операция. Сохранение источника никогда не означает подтверждение факта; это должно следовать из названия действия и состояния карточки, а не из конкурирующих вариантов сохранения.

## 3. Три решения подряд выглядят как повторное подтверждение — P1

**Где:** Analyze:287; ComplexDossier:121–122; CaseSignal:84–90.

Сначала предлагается обосновать и принять/отклонить гипотезу. Потом — обосновать и подтвердить/отклонить факт. Потом — обосновать и подтвердить/вернуть сигнал. Это разные решения, но визуально похожие формы не показывают, какой новый вопрос решается на каждом шаге.

**Изменение:** назвать первый этап «Взять в проверку» / «Отклонить предложение AI», второй — конкретным вопросом о факте и доказательстве, третий — итоговым утверждением заключения. Проводить первые два этапа в одной карточке материала, не переносить человека в новый список. Сохранять различие AI-триажа и проверки человеком в модели и истории. Не переносить комментарий автоматически как обоснование другого решения.

## 4. Досье и расследование почти одинаковы, но статус читается по-разному — P1

**Где:** App.svelte — маршруты complexes/cases; ComplexDossier:29, 107–122.

Оба маршрута используют один компонент, одинаковые вкладки и материалы. Меняются доступные действия и источник оценки. При этом assertions выбираются только по caseId: в режиме без дела карточка утверждения не получает подтверждения из конкретного дела и показывает «Кандидат», хотя сводная оценка объекта может уже учитывать проверенные факты.

**Изменение:** одно досье с явно выбранной проверкой и её статусом; действие «Открыть проверку» меняет рабочий контекст без создания ощущения другого продукта. У факта показывать «Проверен в деле …» либо «Не проверен в выбранном деле», а не безусловное «Кандидат». Не выдавать решение другого дела за решение текущего.

## 5. Повторный поиск источника после перехода — P1, воспроизведено

**Где:** ComplexDossier:120; Publications:10–29,39.

В досье SQ-001 показаны две публикации. «Открыть в публикациях» ведёт на #/publications?complex=SQ-001, но лента показывает «Найдено: 13», фильтр ЖК пустой. complexId используется для Analyze, а фильтр link восстанавливается независимо. Обратный переход из инспектора ведёт к общей проверке ЖК без выбранного evidence.

Человек заново ищет то, что уже выбрал, а затем снова читает тот же текст. Это перегрузка повторной работой, а не только вёрсткой.

**Изменение:** явно переданный объект имеет приоритет над сохранёнными фильтрами; передавать идентичность публикации/материала в обе стороны. Открывать её единственную карточку.

## 6. Два заголовка и две вводные на одной форме — P2, воспроизведено

**Где:** Publications:33–34 + Analyze:265–266.

В добавлении одновременно показаны «ИСТОЧНИКИ И ГИПОТЕЗЫ / Публикации» и «ПУБЛИКАЦИЯ → ГИПОТЕЗА → РЕШЕНИЕ / Проверка объявления». Далее ещё «01 / Исходные данные» и «02 / Гипотезы ИИ». Пользователь нажал «Добавить публикацию», но оказался внутри нескольких конкурирующих названий задачи.

**Изменение:** одна шапка «Добавить публикацию», ссылка назад. Результат анализа появляется после анализа, вместо постоянной пустой панели. Примеры A/B/C — раскрываемая помощь для демо.

## 7. Успех сохранения сообщается до трёх раз — P2

**Где:** App.commit / notice; Analyze:279 и 291.

При успешном сохранении видны глобальное «Изменения сохранены», локальное «Материал сохранён: …» и, если есть result, «Публикация сохранена…». Последние два управляются одним saved. Ни один повтор не добавляет следующего полезного действия.

**Изменение:** одно локальное подтверждение «Публикация сохранена» со ссылкой «Открыть материал / перейти к проверке». Глобальное уведомление подавлять для операции, уже имеющей локальный результат. Ошибки остаются у нужной формы.

## 8. Правовое основание и предупреждение о баллах повторяются в обзоре — P2

**Где:** ComplexDossier:110,117; ComplexForm:40–54.

Основание видно над вкладками, затем в строке «Основание / сверка», затем в факторе R1. Правило «неизвестность не начисляет R1» повторяется через подсказку R1 «Нет данных ≠ R1», а ниже — общее предупреждение о баллах. При редактировании добавляется ещё техническая пара основание/статус.

**Изменение:** одна содержательная карточка основания: результат, источник, дата. У оценки — краткий охват проверки; пояснение расчёта раскрывается по запросу. Для R1 сохранять самостоятельную проверку факта, но использовать ссылку на уже записанное основание вместо повторного набора сведений.

## 9. Объяснения «это не подтверждение» сопровождают почти каждую операцию — P2

Analyze объясняет границу AI во вводной, в панели гипотез и после сохранения. Publications повторяет её в инспекторе. Досье, наблюдения готовности, связи и итог снова объясняют отсутствие автоматических баллов. Футер постоянно повторяет ответственность человека.

Эти пояснения имеют смысл, но постоянное повторение превращает их в фон. Предупреждение не должно компенсировать неясное имя кнопки.

**Изменение:** общий принцип — в справке о методике; конкретное ограничение — у решения, которого оно касается. Например, у R5 показать отсутствующее датированное измерение, у AI — «Предложение AI · ещё не проверено». Нулевой балл и недостаточность данных обозначать рядом с оценкой. Ограничения финального отчёта сохранять.

## 10. Фото и метаданные повторяются независимо от задачи вкладки — P2

**Где:** ComplexDossier:114; MediaCard:19–24; Timeline.

MediaCard уже показывает подпись и дату. Досье повторяет источник/дату под MediaCard и даты в переключателях. Этот aside остаётся и при проверке, и при работе со связями. Материал можно снова открыть внутри источника. На пустом объекте постоянно повторяется сообщение об отсутствии снимков и 3D-модели.

**Изменение:** один просмотрщик выбранного материала с одной подписью. На вкладке связей он не нужен. Пустая галерея — компактная ссылка добавления материала, а не постоянная колонка. Сравнение двух снимков оставлять отдельным полезным режимом, доступным при наличии снимков.

## 11. История показывается в нескольких местах и с разным охватом — P1/P2

**Где:** Analyze:295–299; ComplexDossier:126; Timeline / dossierTimeline.

«Сохранённые решения гипотез» под формой новой публикации выбирает все ai.review рабочего пространства, без фильтра по текущему материалу/ЖК. «Журнал дела» фильтрует audit по complexId, а не caseId. Хронология показывает события и сохранённые решения. Пользователь видит похожие записи в разных местах и не может уверенно понять их область.

**Изменение:** убрать глобальную историю из формы добавления. В карточке материала показывать её решения по запросу. Хронологию использовать для событий объекта; журнал выбранного дела фильтровать по этому делу и открывать из его контекста. Это разные истории, их нельзя слить без сохранения области действия.

## 12. Предпросмотр отчёта повторяет доказательство несколькими блоками — P2

**Где:** CaseSignal:68–82; ComplexDossier.review:99.

Блок фактора выводит цитату и evidence.text. При отсутствии extra evidence.text получает полный artifact.text. Ниже повторяются автор/дата и комментарий в «Обоснованиях проверки фактов», затем весь artifact.text в «Использованных материалах». Так один источник может читаться сначала как цитата, потом как полный текст доказательства, затем снова как полный материал.

**Изменение:** в рабочем предпросмотре одна карточка факта: вывод, цитата, автор, обоснование, ссылка на источник. Полные оригиналы — раскрываемое приложение, каждый материал один раз. Полную версию для печати/архива сохранять; не удалять происхождение и версии ради компактности интерфейса.

## 13. Несколько способов добавления документа повторяют ввод контекста — P2

**Где:** Analyze, RegistryCatalog, ComplexDossier «Добавить документ».

Публикация со скриншотом/PDF сохраняется из Analyze. Документ со связанным текстом — из RegistryCatalog. Обе формы спрашивают объект, очередь, источник, дату, текст и файл, но по-разному называют результат. Из досье добавление документа ведёт просто в каталог, без открытой формы и подставленного ЖК.

**Изменение:** единый компонент «Добавить материал», с вариантом «Публикация / Документ / Наблюдение». Из объекта/дела контекст подставлен. Разные точки входа оставить: это полезные короткие пути, если все открывают одну и ту же форму и карточку результата.

## 14. CSV создаёт второй редактор того же объекта внутри первого — P2

**Где:** Analyze:195–263,300–322.

После выбора строки selectRow копирует её в основную форму; ниже остаётся второй select «ЖК для строки», связанный с тем же selected, отдельное «Подтвердить ЖК» и отдельное сохранение. Источник и даты повторяются в строке, её подсказке, описании активной строки и основной форме.

**Изменение:** отдельный режим массового импорта в той же операции добавления: таблица строк и один редактор выбранной строки. Подтверждение соответствия ЖК показывать только там, где соответствие требует проверки; не держать два редактора одного значения.

## 15. Повторные действия могут создавать уже реальные дубли материалов — P1, по коду

**Где:** Timeline.attach:12; Relations.attach:28; investigation artifact.register:150–155.

Timeline создаёт новый artifact, если у события нет artifactId. Для события из ads не переносится adId. Значит, связь с исходной публикацией теряется; исходная публикация и новое событие могут остаться отдельными элементами хронологии. Повторное добавление исходного события создаёт новый ID. Relations.attach каждый раз создаёт новый REL-материал; кнопка не превращается в «В деле». Регистрация artifact проверяет уникальность ID, а не идентичность исходного события/связи.

**Изменение:** переиспользовать материал по устойчивой идентичности источника и области, переносить adId; повторное включение в дело должно быть идемпотентным. Одинаковый текст разных независимых источников автоматически не склеивать. Перед исправлением воспроизвести сценарий на отдельном наборе данных; сохранением в браузере этот пункт не проверялся.

## 16. Автоматическая и сохранённая связь могут описывать одну пару дважды — P2, по коду

**Где:** dossier-context.ts:11–29.

Сначала формируются связи из карточки, публикаций и документов, затем сохранённые relations добавляются через unshift без согласования с выведенными кандидатами. Один застройщик/документ может оказаться и кандидатом, и подтверждённой связью.

**Изменение:** группировать представления по нормализованным сторонам, типу и области; показывать одну связь и её источники. Различные периоды/области не склеивать. В проверенной связи старую автоматическую подсказку показывать как происхождение, а не вторую самостоятельную связь.

## 17. Два определения статуса публикации — P1, по коду

**Где:** Publications.publicationStatus:13–20 и ComplexDossier.assertions:29.

Лента ищет verified среди утверждений без выбранного дела и считает всю публикацию verified, если проверено хотя бы одно утверждение. Досье определяет факт по выбранному делу; режим без caseId не берёт его assertions. Это не единый статус, хотя надписи похожи. Пользователь начинает повторно проверять то, что кажется «пропавшим».

**Изменение:** отдельный статус источника и прогресс его утверждений: например «1 из 3 проверено», со ссылкой на дело. Не называть всю публикацию проверенной по одному утверждению. Единое правило отображения для всех экранов.

## Что не следует объявлять ненужными дублями

- Оценка в списке и в досье помогает ориентироваться после перехода; проблема — одинаково выглядящие оценки разных дел без подписи.
- Дата публикации и дата фиксации обозначают разные события. Их нельзя заменить одной датой; вторую можно раскрывать в подробностях источника.
- Заявленная и измеренная готовность — разные данные для сравнения, обе нужны.
- AI-триаж, проверка факта и утверждение версии — разные решения; можно сократить переключения и сделать роли ясными, но не автоматически подтверждать одно через другое.
- Карта/список и граф/список — полезные альтернативные способы представления, если сохраняют выбор и состояние.
- Старый Detail.svelte содержит много похожих форм, но обычный detail-маршрут нормализуется в complexes, а App использует Detail с signal=true. Его скрытые формы не включены в доказательства перегрузки текущего интерфейса. Старый Signal доступен отдельным маршрутом; это вопрос совместимости, не подтверждённый основной источник перегрузки.

## Целевая структура без новых разделов

| Сущность | Единственное полное представление | Что показывать в остальных местах |
|---|---|---|
| Материал / публикация | Карточка материала: оригинал, источник, утверждения, состояние включения | Краткое описание и ссылка на ту же карточку |
| Факт | Карточка проверки внутри материала, с контекстом дела | Короткий вывод, статус и ссылка |
| Объект | Досье: сводка, материалы/проверка, связи, хронология | Название, нужные для поиска признаки и оценка с контекстом |
| Проверка / дело | Рабочий контекст в досье | Статус и переход к выбранному делу |
| История | События объекта в хронологии; действия дела в его журнале | Последнее релевантное изменение |
| Заключение | Краткий предпросмотр и полное версионное приложение | Статус версии и действие просмотра/экспорта |

## Очерёдность изменений

1. Слить источники, публикации и утверждения в связанные карточки; устранить повторное включение источников и потерю контекста.
2. Одна кнопка сохранения, одна шапка формы, одно сообщение об успехе. Убрать глобальную историю и пустую панель AI с формы ввода.
3. Унифицировать статусы с явной областью дела; сблизить AI-триаж и проверку факта в одном рабочем месте.
4. Убрать постоянную пустую галерею и повторные предупреждения; оставить точные ограничения у нужных решений.
5. Сократить рабочий предпросмотр отчёта, сохранив полное архивное приложение.
6. Только после этого решать, нужен ли отдельный раздел очереди проверок.

## Критерии готовности

- Один источник отображается один раз в списке материалов независимо от способа добавления.
- Повторное включение источника/события/связи не создаёт новый материал без осмысленной причины.
- У сохранения одна понятная кнопка и одно подтверждение результата.
- После перехода из ЖК видны только его публикации; выбранный источник не приходится искать снова.
- Статус факта не меняется на «Кандидат» только из-за смены представления без объяснения контекста.
- Оригинал, утверждение и форма решения доступны рядом, без трёх независимых списков.
- История новой публикации не показывает решения по другим объектам.
- Итоговое чтение не требует перечитывать полный текст каждого источника несколько раз.
