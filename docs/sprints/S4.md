# S4 — настоящий AI и независимые решения аналитика

Вход: S3 PASS. C5. Порядок S4.1 → S4.5; до платного прогона все детерминированные проверки проходят.

## S4.1 — доверенный журнал запусков

Файлы: Edge index.ts/tests, types/analysis.ts, новая SQL migration `analysis_runs`, RPC review; `tests/unit/analysis-run.test.ts`.

Реализовать C5. Сначала аутентификация и проверка принадлежности zk, затем server write. Роль обычного клиента SELECT only own; прямые INSERT/UPDATE/DELETE denied. Отдельный серверный клиент Edge пишет журнал с секретом только в серверном окружении. Проверить требуемую конфигурацию до запроса к LLM; отсутствие секрета/модели → понятный 503, без успешного run.

Расширить обработку ошибок: invalid input 400/422; unauth 401; quota действительно исчерпана 429; проблема quota DB 503; provider unavailable/invalid JSON/неверная цитата 502; timeout 504 либо единый документированный 502 с отдельным error_code. Не записывать токены в error/raw logs.

Хешировать точный сериализованный input snapshot по фиксированному порядку полей, хранить сам snapshot. Prompt/schema имеют явную константную версию. Ограничения: text 20 000 символов, request 100 000 байт, provider 30 секунд, пользовательская квота 30/час сохраняются. Различать лимит байтов и символов для RU/KZ.

Tests: missing JWT, чужой zk, forged run owner, direct DML, repeated runId, same ID/different input, model missing quote, unknown factor code, whitespace-only quote, too many hypotheses, malformed JSON, 429 vs DB failure, large chunked request. Hypothesis code только R2/R3, максимум 6, у каждой устойчивый ID. На duplicate run не тратить квоту и не делать второй provider call.

При crash после внешнего ответа до записи succeeded: run остаётся pending/failed; не выдавать успех. Повтор прежнего runId не делает скрытого платного повторного запроса; UI предлагает новый запуск с новым ID и объяснением после истечения timeout. Сохранять статус failed/reason, если сервер способен записать его.

## S4.3 — неизменный ввод и отмена

Файлы: Analyze run/save lifecycle, analysis analyze signature, repository session guard; browser tests.

Snapshot включает text, zkId, URL, account, date, platform; attachment manifest при наличии выбранного файла. Пока идёт run, редактирование разрешено, но результат старого snapshot помечается устаревшим и save/review для него блокируется. Можно явно вернуться к сохранённому snapshot, нельзя автоматически подменить его текущими полями.

AbortController на run; abort предыдущего при новом run, unmount и logout. Generation проверять и на success, и на catch/finally. Отмена браузерного запроса не гарантирует отмену серверного платного запроса — журнал run сохраняется. Не очищать новый результат поздней ошибкой старого запроса.

Browser cases: смена текста, ЖК, URL, date, account; повторный запуск; уход/возврат; logout до ответа; response A приходит после B. Ожидание: только B отображается как актуальный, никакая старая callback не сохраняет данные нового пользователя.
