# S5 — сигнальные версии и полный цикл

Вход: S4 PASS. Схема snapshot уже появилась в S2. Теперь завершить C6/UI/export. Порядок S5.1 → S5.4.

## S5.1 — явная машина состояний и выбор версии

Файлы: domain signal commands, SQL, signal-snapshot.ts, Detail.svelte; создать `src/components/Signal.svelte` при необходимости отделения экрана.

Переходы:

| Из | Действие | Результат |
|---|---|---|
| Нет сигнала/draft | Подтвердить при наличии valid confirmed factors + comment | append revision N confirmed |
| Draft | Вернуть с причиной | append revision N returned, счёт не меняется |
| Confirmed/returned | Новые факты/решения | новый draft basedOnRevision=N; N неизменна |
| Confirmed/returned | Открыть пересмотр с причиной | draft; затем новое решение |
| Любое | Тот же commandId повторно | прежний receipt, без новой версии |
| Draft без confirmed факторов | Подтвердить | отказ |

Экран выбирает текущий draft или историческую revision. Весь header/body/score/status/ads берётся из одного view model выбранной версии. Для исторической версии управление редактированием отсутствует; переход к текущему объекту явный. Нельзя использовать live ads.find для исторической quote/source.

## S5.2 — полный snapshot и доказательства

Файлы: snapshot builder, SQL snapshot builder, Detail/Signal, unit fixtures.

Снимок включает только относящиеся к этому сигналу материалы, полные тексты и источники; чужие объекты не попадут в экспорт. Проверить отсутствие dangling references и итоговый score по weightsVersion. Большие бинарные файлы не в JSON snapshot; manifest/hash и защищённый download по ID. Указание временной signed URL не заменяет provenance.

Test: confirm v1 с R1/R2 и ad URL A → изменить объект/доказательства/публикации допустимой новой командой либо добавить новый ad и пересмотреть фактор → v1 byte-equivalent, draft использует новое; confirm v2 → обе версии доступны после reload, v1 URL/score неизменны. Если редактирование ad не поддерживается, не добавлять отдельный CRUD только ради теста: заменить ссылку фактора на новую публикацию и проверить снимок старой.

## S5.3 — печать/PDF

Файлы: Signal/Detail, app.css print; `tests/e2e/signal-export.spec.ts`.

Экспорт через browser print допустим. Добавить ID/revision, sourceVersion, status, время/автора/comment, объект/происхождение, legal review, веса/score/zone, каждый confirmed factor с quote/source/date/ad date/captureAt и material IDs. Unknown явно обозначен. Фраза о признаках риска, не факте правонарушения, присутствует.

Print styles: убрать controls/navigation, сохранить status/header, не обрезать длинные URL/quote, большие блоки разрешить переносить между страницами. Draft/returned/legacyIncomplete маркировать; incomplete не выдавать за полную утверждённую карточку. Минимум 3 PDF fixtures: короткая confirmed, многостраничная с >280-char quote/длинным URL/RU+KZ, returned или draft.

Проверить автоматически текст/ID/revision/score и реально отрендерить PDF в изображения, осмотреть **все** страницы. Артефакты: PDF, изображения, краткий checklist с обнаруженными проблемами/результатом. Один успешный вызов page.pdf не закрывает критерий.

## S5.4 — полный новый кейс без seed shortcuts

Файлы: tests/live/investigation.spec.ts, tools/local-smoke/deepseek smoke integration.

На synthetic новом ЖК: документированная сверка основания → новая реклама → AI → evidence → human accept R2/R3 (с материалом до ввода) → R1 вручную → score 70/red → confirm v1 → PDF → reload → снять R2 с причиной → draft score 45/yellow → v1 остаётся 70/red → returned с причиной → история видна. Дополнительный путь: отказаться от R2 сразу, score не увеличивается.

Избежать лишних платных запросов: один live AI run можно использовать для полного кейса; остальные branch tests используют фиксированный authenticated run fixture в тестовом окружении, не маркируя их live provider проверкой. Не вставлять fake runs в пользовательскую production-базу.

### Definition of Done

| ID | Свидетельство |
|---|---|
| D5.1 | Все переходы и повторные команды проверены, версии append-only |
| D5.2 | v1 неизменна при новых фактах; header/body/exports согласованы |
| D5.3 | Три PDF созданы, текст сверён, все страницы визуально просмотрены |
| D5.4 | Новый полный connected кейс + отказ + reload/direct link/mobile PASS |
| D5.5 | T/U/B/E/C/A/L + нужный live AI кейс, прежняя регрессия |

После заполнения всех критериев выполнить `npm run gate -- 5`. Его exit 0 — результат проверки отчёта и разрешение перехода, а не заранее проставляемый критерий. При ненулевом exit исправить отчёт/работу и повторить gate.
