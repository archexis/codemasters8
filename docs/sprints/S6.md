# S6 — безопасность и сдаваемая версия

Вход: S5 PASS. Не добавлять новые продуктовые возможности. Порядок S6.1 → S6.5; найденные дефекты исправляются с повтором затронутых gates.

## S6.1 — закрытая матрица безопасности

Файлы: tests/live/security.spec.ts, API/Edge tests, SQL security tests, docs/acceptance/security.md.

| Actor / действие | Ожидание |
|---|---|
| Anonymous: read/write workspace, invoke write RPC, AI, download evidence, API export | отказ, данные не возвращаются |
| B: читать/изменить A workspace или передать A zk/media/run IDs | отказ/пустой own read, без утечки |
| A: прямой UPDATE workspace/audit, старый overload apply_command | denied |
| A: изменить owner/reviewer/time через payload | не получает чужие полномочия, автор серверный |
| A: удалить referenced evidence | denied; unrelated staged own file cleanup разрешён |
| A: javascript:/data: URL, HTML/script в text/name/comment | URL rejected; строки отображены как текст, скрипт не выполняется |
| A: неверный MIME, >20MB upload, path чужого owner | denied; без принятого решения |
| A: request >100000 bytes, text >20000, quota overflow | предсказуемая ошибка, без лишнего provider call |
| A: expired/invalid JWT на API/Edge/RPC | отказ; отсутствие падения UI |
| Service/LLM timeout | ошибка и retry по контракту, без скрытого regex success |
| Logout A/login B + in-flight load/save/AI | поздний ответ A не появляется в B |

Проверка секретов: tracked/untracked файлы в scope, Git history, dist и browser storage/network. Не выводить значения найденных секретов; отчёт содержит только путь/тип/наличие. Публичный publishable/anon key не путать с service_role/LLM secret. При реальном утекшем секрете блокировать сдачу и описать необходимую замену/отзыв, не считать удаление из текущего файла достаточным.

Проверить зависимости по актуальному audit; значимые уязвимости, достигающие сценария приложения, устранить либо точно обосновать неприменимость. Не делать массовый major upgrade наугад.

## S6.2 — финальная UX/regression матрица

Файлы: tests/e2e, tests/live, app.css/components только для найденных ошибок.

Desktop Chromium и mobile viewport; keyboard-only основной путь. Focus виден, label связан, error/status доступны, форма не теряется после ошибки. Прямые 7 маршрутов, неизвестный маршрут/ID, пустое workspace, ноль найденных объектов, отказ tiles/WebGL, offline save, expired session. Независимый список остаётся доступен без карты.

Исправление не считается завершённым без regression test для воспроизведённого дефекта. Не начинать redesign.

## S6.3 — clean-room запуск и восстановление

Файлы: README, .env.example, lockfiles/config, новый `docs/RELEASE_RUNBOOK.md`.

Скопировать именно release candidate в новую изолированную директорию без node_modules/.env/.venv/generated output; переносить исходники по manifest, включая нужные untracked, а не clone старого HEAD. Установить по lockfiles, запустить по README. Использовать отдельную тестовую конфигурацию/пространство; не перезаписывать рабочие env или базу.

Воспроизвести DEMO и подключённый режим, миграции с нуля и upgrade fixture со старой схемы, загрузку демоданных, новый кейс и restore пакета. В инструкции перечислить новые серверные env для analysis_runs writer, миграции, лимиты, missing-data policy и команды проверки.

Release rollback: backup данных/байтов перед upgrade; совместимая старая версия приложения или восстановление полного backup в отдельную среду. Не рекомендовать произвольный down migration с потерей истории.

## S6.4 — release candidate и материалы

Файлы: docs/RELEASE_MANIFEST.json, docs/DEMO_SCRIPT.md, docs/acceptance/requirements.md; PDF и резервные материалы.

Сценарий демонстрации: проблема → новый текст → реальный AI → человек → объяснимый score → версия сигнала → PDF → изменение факта и сохранённая история. Обозначить synthetic данные. Резервная запись либо комплект последовательных скриншотов/PDF с пояснениями показывает тот же кейс; не выдавать запись за live inference.

Зафиксировать исходники release candidate отдельным reviewable commit только с относящимися к работе файлами, не `git add .` вслепую. Если commit в этом окружении невозможен, release gate BLOCKED: manifest полезен для разработки, но сдаваемый SHA ещё не создан. Публикация/пуш/подача заявки — отдельный внешний шаг; этот план сам по себе не разрешает отправку сообщения жюри.

Анонимно проверить доступность предназначенного для жюри репозитория и присутствие **сдаваемого** SHA, не только старой main. Если candidate ещё не опубликован, честно BLOCKED для требования доступной сдаваемой версии; подготовить конкретный diff/commit и необходимое действие пользователю. Не объявлять готовую локальную копию уже доступной жюри.

## S6.5 — итоговая приёмка

После последней правки product code запустить T/U/B/E/C/A/F/L и AI eval на зафиксированном candidate. Сохранить отчёты. Если изменялись только документы, повторять дорогостоящий inference не нужно; указать, что hashes его входных code/prompt/schema не изменились.

Сверить весь requirements matrix: обязательные строки PASS с evidence, необязательные out-of-scope явно помечены. Все прежние gates имеют подтверждённую регрессию. Оставшиеся cosmetic задачи не нарушают ни один DoD.

### Definition of Done

| ID | Свидетельство |
|---|---|
| D6.1 | Вся security matrix PASS, нет неисправленных утечек/обходов/потери данных |
| D6.2 | Desktop/mobile/keyboard/empty/error/deep-link matrix PASS |
| D6.3 | Clean-room DEMO/connected + fresh/upgrade/restore проверены по инструкции |
| D6.4 | Manifest/SHA, сценарий, PDF и резервные материалы готовы; адресат может получить сдаваемые исходники |
| D6.5 | Все обязательные требования и профили PASS на candidate |

Финальный отчёт разделяет: что готово локально, что доступно адресату и что фактически отправлено. Последнее нельзя утверждать без выполненного действия.

После заполнения всех критериев выполнить `npm run gate -- 6`. Его exit 0 — результат проверки отчёта и разрешение перехода, а не заранее проставляемый критерий. При ненулевом exit исправить отчёт/работу и повторить gate.
