## S3.2 — единый dedupe и source contract

Файлы: parser dedupe/detectPlatform, domain, SQL новая migration, `tests/unit/source-contract.test.ts`.

Одна спецификация C4, одинаковый fixture corpus TS/SQL. Cases: регистр/пробелы → duplicate; 8(701)…/+7701… → duplicate; одинаковые первые 60 символов с разным концом → разные; одинаковый текст в другом ЖК → допустим; повтор ID → отказ независимо от текста. SQL не принимает поддельный canonicalKey. Сначала найти существующие совпадения legacy: не удалять публикации/историю, пометить возможные дубликаты; правило действует на новые записи.

Площадки: krisha.kz и его корректный subdomain распознаны; evilkrisha.kz, krisha.kz.evil.test, attacker.test/krisha.kz, URL userinfo не распознаются как Krisha. Если ручная подсказка противоречит URL, показывать `via=manual/hint`, не заявлять проверенный домен. URL разрешены только HTTP(S), parse одинаков по смыслу TS/SQL; пустой URL допустим для ручного документа.

## S3.3 — надёжный построчный CSV

Файлы: parser parseCsvAds, Analyze CSV section, types; создать `tests/e2e/csv-import.spec.ts`.

Сохранить PapaParse. Добавить rowId/номер/errors/mappedZkId/savedAdId. BOM, comma/semicolon, escaped quotes, multiline, пустая строка и лишние столбцы. Строки с parse error не могут попасть в save. При выборе строки сбрасывать все значения формы и старый analysis. Непустой hint: exact ID match → предварительное сопоставление; unique name → предложение; unknown/ambiguous → null и кнопка save disabled до выбора. Подтверждение ЖК требуется до сохранения.

Дата неизвестна → null, не предыдущая/сегодня. Date 2026-02-30 — ошибка. После сохранения первая строка отмечена и не импортируется второй раз; вторая строка может быть обработана независимо. Сохранение без анализа допустимо как публикация без подтверждённых факторов; AI не обязательный dependency импорта.
