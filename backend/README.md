# Сервер SAQ QURYLYS

Установка: `python -m pip install -r backend/requirements.lock.txt`. Запуск из корня: `python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000`.

Нужны `SUPABASE_URL`, `SUPABASE_ANON_KEY`; пользовательский Bearer JWT проверяется через Auth, запросы в PostgREST и Storage выполняются с тем же токеном и RLS. Service role ключ серверу не нужен. До использования новых команд и jobs примените новую миграцию обычным процессом выпуска; в этой работе удалённая база не изменялась.

Сохранены `/health`, `/api/summary`, `/api/export`. Небольшие представления: `/api/map-summary`, `/api/publications`, `/api/registry`, `/api/complexes/{id}/preview`, `/dossier`, `/verification`, `/relations`, `/timeline`, `/api/cases/{id}`. У представлений досье `phase_id` ограничивает область. Списки используют `limit` и `cursor`; граф ограничен одним переходом. Backend пока читает JSONB workspace целиком внутри сервера; перенос физического хранения в отдельные индексированные сущности не выполнен.

PDF сохранённого решения: `GET /api/cases/{caseId}/snapshots/{snapshotId}/pdf`. Renderer использует только сохранённый snapshot. Для кириллицы нужен `PDF_FONT_PATH` или системный DejaVu Sans/Arial; Docker устанавливает DejaVu Sans.

`POST /api/import/pdf` принимает raw `application/pdf` до 20 МБ/100 страниц и возвращает непроверенный candidate с постраничным текстом и SHA256. Изображения: `POST /api/import/image`, JPG/PNG/WebP до 20 МБ/25 мегапикселей. OCR использует локальный Tesseract с `rus+eng`; отсутствие возвращает 503. Docker устанавливает Tesseract, однако его OCR качество на реальных документах отдельно не проверено. Текст OCR всегда требует сверки с оригиналом.

Фоновый вариант PDF: `POST /api/document-jobs?complex_id=...&kind=pdf-text|ocr`, тот же raw PDF. Оригинал сохраняется в приватном Storage, metadata — в `document_jobs`, ответ 202 с `pollUrl`. Worker обрабатывает максимум два документа одновременно. PDF OCR читает встроенные растровые изображения, максимум 20 страниц/5 изображений на страницу и ограничивает время; это не универсальный PDF renderer. Статусы: queued/running/succeeded/failed. После перезапуска незавершённую задачу можно возобновить авторизованным `POST /api/document-jobs/{id}/retry`: токены не сохраняются в очереди. Автоматического перезапуска без пользовательского токена нет. Queue output не подтверждает факты и не влияет на риск.

Проверки: `python -m pytest backend/tests -q`; SQL boundary: `npx vitest run tests/unit/investigation-sql.test.ts`. Тесты используют локальный HTTP mock/PGlite; это не проверка развёрнутого Supabase, Docker или установленного OCR.

Переход старого workspace выполняется без потери истории. После первого нового дела по ЖК сервер отклоняет подтверждения старых команд `factor`, `ad+hypothesis`, `signal`: решения выполняются через `fact.review`/`case.decide`. Старые квитанции продолжают безопасно повторяться. ЖК без новых дел сохраняют legacy путь для совместимости. Изменение исходных правовых/строительных данных отзывает зависимые текущие утверждения в `candidate`, возвращает дело в draft; исторические snapshots сохраняются. При restore активные verified становятся candidate, дела draft, геометрия verified=false, исторические snapshots получают imported=true.

Очереди используют собственные readiness observations: история `readinessSources` добавляется только в конец; сведения всего ЖК не подтверждают R5 отдельной очереди. `period` задаёт включительный интервал `{from,to?}`; известный период дела должен покрываться утверждением, для R1 — применимым основанием, для R3 — датами публикации/доказательства. Snapshot сохраняет период и собственные наблюдения очереди.

Типизированные контекстные связи хранятся в `relations`: `relation.register` создаёт candidate, отдельный `relation.review` сохраняет human review. Проверяются канонические узлы, область первичных материалов, отсутствие self-edge. Подтверждение требует непустого списка материалов и комментария; связи не добавляют риск-баллы. Backend graph возвращает сохранённые рёбра, статусы и ссылки на первоисточники; для legacy без связей остаётся отдельно помеченная identity-проекция реестра.

## Автоматическая подготовка существующего расследования

Кнопка «Начать расследование» в досье создаёт дело и открывает вкладку «Проверка». Один проход сначала вносит сохранённые публикации, разбирает документы и доступные вложения, затем ставит внешний сбор в серверную очередь. Повторный вход продолжает то же дело. Прогресс, ограничения, ручное добавление, неоднозначные находки и мониторинг находятся прямо в досье.

Подготовка использует только `artifact.register`, `case.attach` и `claim.propose` (для новых веб-публикаций также `ad`). Она не выполняет `ai.review`, `fact.review`, `case.decide` или `case.reopen`. Для подтверждения пользователь выбирает отдельный факт или явно отмечает пакет; изначально ничего не выделено. Весь пакет проходит существующие проверки до первой записи. Команды доставляются последовательно с сохранением ID и позиции при потерянном ACK; частичный commit показан в UI. Серверные проверки каждой команды остаются обязательными.

### Настройки сервера

| Переменная | Назначение |
| --- | --- |
| `TAVILY_API_KEY` | Включает внешний поиск. Без ключа UI явно показывает недоступность; обработка существующих текстов остаётся доступной. |
| `RESEARCH_DOMAINS` | Приоритетные домены через запятую. По умолчанию `gov.kz,homeportal.kz,krisha.kz`: государственные публикации, жилищный портал и объявления. Это приоритеты поиска, а не доверенные доказательства. Домены следует подобрать для территории/источников оператора. |
| `RESEARCH_DB_PATH` | SQLite, по умолчанию `backend/.data/research.sqlite3`. **Нужен постоянный локальный volume** с правом записи пользователя процесса. В Docker монтировать `/app/backend/.data`; для другого пути установить переменную. Не использовать эфемерную файловую систему/serverless для мониторинга. |
| `SUPABASE_SERVICE_ROLE_KEY` | Необязательный секрет только сервера. Нужен для мониторинга: перед каждым проходом сервер заново читает `workspaces` с явным `owner_id`, проверяет существование дела, актуальные объект/очередь/период. Без него мониторинг отключён. В браузер ключ не передаётся. Обычным API-маршрутам он не нужен. |

`GET /api/cases/{id}/research` возвращает доступность, текущую работу, историю результатов и настройки мониторинга. `POST` на тот же адрес запускает сбор; `POST .../research/monitor` принимает `{ "monitor_hours": 0|6|24|168 }`. Все маршруты требуют текущий пользовательский JWT и owner-scoped workspace через RLS. JWT не сохраняется в SQLite. Мониторинг по умолчанию выключен.

FastAPI lifespan запускает worker. SQLite ограничивает очередь 32 активными работами; `BEGIN IMMEDIATE` предотвращает двойной claim между процессами на одном локальном volume. Lease 10 минут; вызовы поиска ограничены временем, просроченная работа восстанавливается после рестарта. Token lease не позволяет старому worker перезаписать результат нового. История ограничена примерно 20 завершёнными проходами на дело. Каталог с SQLite содержит пользовательские материалы: включите его в защищённое резервное копирование, ограничьте доступ правами ОС. Для распределённых хостов нужен единый сервис очереди вместо копий SQLite.

### Анализ и ограничения

- В DEMO выполняется настоящий локальный RU/KZ parser из `analysis.ts`; сеть, LLM и OCR не имитируются. В подключённом workspace используется существующая Edge Function `analyze` с точными входными snapshots, runId и проверкой цитат. Недоступность анализа показывается как ограничение конкретного материала.
- Серверный мониторинг работает при закрытом браузере: сохраняет оригинальные тексты и предварительные R2-кандидаты **локальными правилами, без LLM**. При открытии активного дела подходящие находки вносятся каноническими командами и могут проходить существующий LLM-разбор. Подтверждённое/возвращённое дело автоматически не открывается: новые находки остаются отдельно до ручного пересмотра.
- Выполняются два ограниченных запроса: выбранные в досье приоритетные домены, затем общий поиск. Если все приоритеты сняты, выполняется только общий поиск. Выбор сохраняется в работе и настройках мониторинга. Сбой одного сохраняет результат другого; отсутствие находок и ошибка различаются. Ответ провайдера ограничен 2 МБ, 12 находками, по 30 000 символов; слишком длинный/обрезанный текст не считается полным оригиналом. Для LLM разбираются первые 20 000 символов с явным сообщением об оставшемся тексте.
- Автопривязка намеренно редкая: один набор отдельных полей «ЖК/Объект», «Адрес», «Застройщик» с точными значениями, для очереди — также точное поле очереди. Каталоги, противоречия, другие очереди, фрагменты без оригинала, неизвестные даты и даты вне периода требуют уточнения. Названия и БИН сами по себе недостаточны. Внешние тексты никогда не выполняются как инструкции.
- Сохраняются URL, исходный текст, дата публикации отдельно от времени фиксации и причина сопоставления. Метаданные поиска также остаются в SQLite; время исходной фиксации и причина переноса включены в источник Evidence Ledger. Дата загрузки вложения не становится датой события.
- Публикации и вложения без установленной очереди автоматически в дело конкретной очереди не переносятся. Материалы без даты/вне периода доступны для ручного уточнения. PDF/OCR используют существующие обработчики; отсутствие OCR/оригинала показано явно. Полный LLM-разбор требует открытого клиента; первичный серверный мониторинг этого не обещает.
- Новый сбор при изменённой цели использует актуальные метаданные. Старые находки не переносятся в изменённую область автоматически. Удалённое дело отключает мониторинг при следующей проверке. Обнаруженные материалы не переписывают решения или сохранённые версии сигнала. Отсутствие результатов поиска не создаёт R1.

Проверки реализации: `backend/tests/test_research.py`, `tests/unit/preparation.test.ts`, браузерные сценарии `investigation-lifecycle`, `case-retry`, `investigation-score`, `legal-invariants`. HTTP-mock тесты не доказывают доступность оплаченного Tavily, Edge LLM или инфраструктуры volume.
